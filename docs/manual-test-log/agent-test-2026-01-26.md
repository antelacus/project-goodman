## 发现的问题

### 1. Q18: 营业成本查询失败

**现象**: 用户问"2024年营业成本是多少？"，agent 返回"无法找到2024年'营业总成本-营业成本'的数据"。

**根本原因**: LLM 传递了部分规范键 `"营业总成本-营业成本"` 而非简单标签 `"营业成本"`。metric-registry.ts 中的别名只包含：
- `"营业成本"` (label)
- `"利润表-营业总成本-营业成本"` (完整规范键)
- `"其中：营业成本"` (alias)

但不包含 `"营业总成本-营业成本"` (部分规范键)。

**数据库验证**: 数据存在，metric_name = `"利润表-营业总成本-营业成本"`，value = 6414412418.58

**修复方案**:
1. 在 metric-registry.ts 中为 `IS.OPERATING_COSTS` 添加别名 `"营业总成本-营业成本"`
2. 或改进 normalizeName 函数以处理部分规范键

### 2. Q55-Q57: 文档搜索失败

**现象**: search_documents 工具调用返回 `RETRIEVAL_FAILED` 错误。

**根本原因**: PostgreSQL 函数 `search_documents_hybrid` 的 search_path 设置问题。

函数定义中有：
```sql
SET search_path TO 'public'
```

但 pgvector 的 `<=>` 运算符在 `extensions` schema 中，导致错误：
```
operator does not exist: extensions.vector <=> extensions.vector
```

**修复方案**: 更新函数的 search_path：
```sql
SET search_path TO 'public', 'extensions'
```

需要创建新的数据库迁移来修复此问题。

### 3. Q59: 法规搜索优先级问题（提示词增强）

**现象**: 用户问"存货跌价准备的相关规定？"，agent 返回了通用会计准则内容。

**期望行为**: 当用户未明确要求查询会计准则/法规时，应优先搜索公司相关文档（如公司基本档案、财务管理制度），找不到再提供通用内容。

**修复方案**: 增强系统提示词，明确搜索优先级：
1. 先搜索公司相关文档
2. 找不到再搜索通用法规/准则
3. 明确告知用户信息来源

### 4. Q66-Q67: Agent 要求澄清公司名称

**现象**:
- Q66: "帮我查一下2024年账上有多少钱" → Agent 问"请问您需要查询的是哪家公司？"
- Q67: "公司欠了多少钱？" → Agent 问"我需要知道您想查询哪家公司"

**根本原因**: 系统提示词未明确 agent 服务于单一公司。

**修复方案**: 更新系统提示词，明确：
- Agent 服务于特定公司的财务人员
- 无需询问公司名称
- 默认查询当前公司数据

### 5. Q70: 毛利率查询未要求年份澄清

**现象**: 用户问"毛利率怎么样？"，agent 直接返回2024年数据。

**期望行为**: 对于未指定年份的查询，应先询问用户想查询哪一年。

**修复方案**: 更新系统提示词或工具调用逻辑，对于模糊的时间范围查询要求澄清。
