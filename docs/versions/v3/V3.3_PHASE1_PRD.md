## 1. 概述

### 1.1 产品愿景

将 Project Goodman 从"AI 辅助工具"升级为"AI Agent"，使系统能够自主发现和选择相关文档，同时保持用户对最终决策的控制权。

### 1.2 一句话描述

**智能文档系统**：AI 自动搜索并选择相关文档进行分析，用户可查看来源并在需要时手动覆盖。

### 1.3 背景

当前系统 (V2) 要求用户在提问前手动选择文档。这种方式存在以下问题：

- 用户需要了解哪些文档包含所需信息
- 用户可能遗漏相关文档
- 操作繁琐，影响用户体验

V3.3 智能文档系统将实现 AI 驱动的文档自动发现和选择，同时通过透明化机制让用户了解 AI 的选择依据。

## 2. 问题陈述

### 2.1 当前痛点

| 痛点 | 影响 | 频率 |
|------|------|------|
| **手动文档选择** | 用户需预先知道答案在哪个文档中 | 每次查询 |
| **遗漏相关文档** | 分析结果不完整或不准确 | 经常 |
| **财务报告难以利用** | 项目注释中的详细数据无法精确检索 | 经常 |
| **搜索噪声** | 通用词（如"折旧"）返回过多不相关结果 | 经常 |

### 2.2 核心问题

> 用户提出财务分析问题时，需要手动选择文档，而非让 AI 自动找到最相关的信息来源。

### 2.3 目标状态

```
当前 (V2):
用户 → 手动选择文档 → AI 从选定文档提取 → 返回结果
        ↑
    用户负担：需要知道信息在哪

目标 (V3.3):
用户 → 提问 → AI 自动搜索文档 → AI 选择最相关文档 → 提取并分析 → 返回结果 + 来源
                                                                      ↓
                                                           用户可查看并覆盖选择
```

## 3. 用户画像

### 3.1 主要用户：财务分析师

| 属性 | 描述 |
|------|------|
| **角色** | 企业财务人员、财务顾问 |
| **目标** | 快速获取准确的财务分析结果 |
| **技术水平** | 熟悉财务概念，非技术专家 |
| **核心需求** | 信任 AI 选择，但需要验证来源 |
| **痛点** | 不想花时间寻找正确的文档 |

**典型场景**：
> "我想知道公司 2024 年的折旧与摊销金额。我知道这个数据在财务报告的某个地方，但不想翻阅整份文档去找。"

### 3.2 次要用户：系统管理员

| 属性 | 描述 |
|------|------|
| **角色** | 负责上传和管理文档 |
| **目标** | 确保文档被正确处理和索引 |
| **技术水平** | 中等技术水平 |
| **核心需求** | 了解文档处理质量 |
| **痛点** | 不清楚上传的文档是否能被有效检索 |

**典型场景**：
> "我上传了一份财务报告，想确认系统能正确识别其中的章节结构。"

## 4. 用户故事

### 4.1 核心用户故事

#### US-1: 自动文档选择

```
作为 财务分析师
我希望 系统自动找到回答我问题所需的文档
以便 我不需要预先知道信息存储在哪里
```

**验收标准**：

- [ ] 用户提问后，系统自动搜索相关文档
- [ ] 系统选择最相关的文档（最多 N 个）
- [ ] 在 30 秒内返回搜索结果

#### US-2: 来源透明化

```
作为 财务分析师
我希望 看到 AI 选择了哪些文档作为信息来源
以便 我可以验证结果的可靠性
```

**验收标准**：

- [ ] 结果显示所使用的文档列表
- [ ] 每个文档显示相关度评分或选择原因
- [ ] 可点击查看文档具体内容

#### US-3: 手动覆盖

```
作为 财务分析师
我希望 在 AI 选择不当时能手动指定文档
以便 我可以纠正错误并获得正确结果
```

**验收标准**：

- [ ] 用户可取消选择 AI 推荐的文档
- [ ] 用户可添加 AI 未选择的文档
- [ ] 修改后可重新执行分析

#### US-4: 财务报告精确检索

```
作为 财务分析师
我希望 从财务报告的项目注释中获取精确数据
以便 我可以进行详细的财务分析（如折旧与摊销明细）
```

**验收标准**：

- [ ] 系统能识别财务报告的章节结构
- [ ] 搜索结果按章节过滤，减少噪声
- [ ] 返回的数据包含具体数值和上下文

### 4.2 管理员用户故事

#### US-5: 文档结构识别反馈

```
作为 系统管理员
我希望 上传财务报告后看到结构识别质量
以便 我知道文档是否能被有效检索
```

**验收标准**：

- [ ] 上传后显示结构识别结果（良好/一般/基础）
- [ ] 显示识别到的章节数量
- [ ] 如果识别质量低，显示改进建议

#### US-6: 上传指引

```
作为 系统管理员
我希望 了解什么样的文档格式效果最好
以便 我可以准备符合要求的文档
```

**验收标准**：

- [ ] 上传界面显示文档格式建议
- [ ] 说明包含目录的文档效果更好
- [ ] 提供示例或最佳实践指南

## 9. 范围定义

### 9.1 包含在范围内 (In Scope)

| 类别 | 内容 |
|------|------|
| **文档搜索** | 混合搜索 API、章节过滤、相关度评分 |
| **文档处理** | 财务报告章节识别、元数据标记、降级处理 |
| **工作流集成** | 财务分析、合规指导的自动文档选择 |
| **用户界面** | 来源显示、手动覆盖、上传反馈 |
| **文档类型** | 增强现有 `financial_report` 处理 |

### 9.2 排除在范围外 (Out of Scope)

| 内容 | 原因 | 未来版本 |
|------|------|----------|
| 新文档类型定义 | 使用现有类型即可满足需求 | - |
| 上传时数据预提取 | 采用章节感知搜索方案，运行时检索而非预提取 | 如搜索效果不佳可考虑 |
| 复杂分析报告生成 | 需要不同的工作流设计（多文档确认、报告模板等），作为独立功能开发 | V3.8+ |
| 查询复杂度分类 | 当前所有查询使用统一的自动选择流程 | 与复杂分析功能一起实现 |
| 多语言支持 | 当前仅支持中文 | V4+ |
| 文档 OCR | 假设 PDF 为可搜索格式 | 需要时添加 |
| 历史查询学习 | 基于用户历史优化选择 | V4+ |

### 9.3 假设与约束

**假设**：

1. 财务报告 PDF 为可搜索格式（非扫描图片）
2. 大多数财务报告包含目录或清晰的章节标题
3. 用户提问使用中文

**约束**：

1. 必须在现有 V3.1 工作流架构上构建
2. 不引入新的外部依赖（除必要库外）
3. 保持向后兼容（现有 API 契约不变）
4. 当前版本不区分简单查询与复杂分析，所有查询使用相同的自动选择流程

## 10. 风险与缓解措施

| 风险 | 可能性 | 影响 | 缓解措施 |
|------|--------|------|----------|
| **章节识别准确率低** | 中 | 高 | 多重检测策略 + 优雅降级 |
| **搜索结果噪声大** | 中 | 中 | 章节过滤 + 相关度阈值 |
| **响应时间过长** | 低 | 中 | 并行搜索 + 结果缓存 |
| **用户不信任自动选择** | 低 | 中 | 透明化显示 + 易用的覆盖操作 |
