## 1. 执行摘要

### 1.1 目的

将 Project Goodman 从 Vercel (serverless) 迁移到自托管 VPS，以支持 AI Agent 架构特性，这些特性需要长时间运行的进程、WebSocket 连接和后台任务。

### 1.2 背景

当前的 Vercel 部署存在硬性限制，阻碍了 V3 路线图的发展：

| Vercel 限制 | 影响 | VPS 解决方案 |
|---|---|---|
| 60秒函数超时 (60-second function timeout) | 无法运行多步骤 AI Agent 链 | 无超时限制 |
| 不支持 WebSocket | 无法流式传输 Agent 的“思考”步骤 | 全面支持 WebSocket |
| 无后台任务 | 无法预处理文档 | PM2 worker 进程 |
| 无状态执行 (Stateless execution) | 请求之间无记忆 | 可实现内存缓存 |

### 1.3 范围 (Scope)

**包含范围 (In Scope):**

- VPS 基础设施设置 (nginx, PM2, Node.js)
- 应用程序部署和配置
- 通过 Cloudflare Origin Certificate 进行 SSL/TLS 配置
- DNS 从 Vercel 迁移到 VPS
-以此安全性加固 (防火墙, 访问控制)

**不包含范围 (Out of Scope):**

- 应用程序代码更改 (无需更改)
- Redis 安装 (推迟至 V3.2)
- WebSocket 实现 (推迟至 V3.1)
- CI/CD 自动化 (未来增强)
- 预发布环境 (Staging environment) (目前仅单个环境)

## 4. 需求 (Requirements)

### 4.1 功能需求 (Functional Requirements)

| ID | 需求 (Requirement) | 优先级 (Priority) | 验收标准 (Acceptance Criteria) |
|---|---|---|---|
| FR-1 | 应用程序可通过 `goodman.antelacus.com` 访问 | Critical | URL 加载应用程序主页 |
| FR-2 | 所有现有功能工作方式相同 | Critical | 所有 14 个 API 端点返回预期响应 |
| FR-3 | 应用程序在崩溃时自动重启 | Critical | `pm2 kill` 后自动恢复 |
| FR-4 | 应用程序在 VPS 重启后启动 | Critical | 重启 VPS，应用在 2 分钟内可访问 |
| FR-5 | 零停机部署能力 | High | `pm2 reload` 更新时不丢失请求 |
| FR-6 | 支持 WebSocket 连接 | High | WebSocket 握手成功 (针对 V3.1) |
| FR-7 | 无执行超时 | High | 运行时间 >60s 的 API 请求成功完成 |

### 4.2 非功能需求 (Non-Functional Requirements)

| ID | 需求 (Requirement) | 优先级 (Priority) | 验收标准 (Acceptance Criteria) |
|---|---|---|---|
| NFR-1 | 页面加载时间 < 3 秒 | High | Lighthouse 或浏览器 DevTools 测量 |
| NFR-2 | API 响应时间 < 500ms (非 AI) | High | 简单端点响应迅速 |
| NFR-3 | 内存使用 < 3GB | Medium | `pm2 monit` 显示 < 3GB |
| NFR-4 | 日志可访问 | Medium | `pm2 logs` 显示应用程序输出 |
| NFR-5 | 99% 正常运行时间 (Uptime) | High | 监控显示可用性 |

### 4.3 安全需求 (Security Requirements)

| ID | 需求 (Requirement) | 优先级 (Priority) | 验收标准 (Acceptance Criteria) |
|---|---|---|---|
| SR-1 | 强制 HTTPS | Critical | HTTP 请求重定向到 HTTPS |
| SR-2 | 有效的 SSL 证书 | Critical | 浏览器显示挂锁图标，无警告 |
| SR-3 | 启用防火墙 | Critical | 仅开放端口 22, 80, 443 |
| SR-4 | 阻止直接 IP 访问 | High | `http://104.168.38.213` 返回错误 |
| SR-5 | 仅 Cloudflare IP 可通过 nginx | High | 非 Cloudflare IP 被拒绝 |
| SR-6 | 环境变量安全 | Critical | 机密信息不在代码仓库中 |
| SR-7 | SSH 访问安全 | High | 密码或基于密钥的身份验证 |

## 6. 风险评估 (Risk Assessment)

| 风险 (Risk) | 可能性 (Likelihood) | 影响 (Impact) | 缓解措施 (Mitigation) |
|---|---|---|---|
| DNS 传播延迟 | Medium | Low | 在低流量期间计划迁移 |
| 配置错误 | Medium | Medium | 在 DNS 切换前彻底测试 |
| VPS 性能问题 | Low | Medium | 监控资源，必要时优化 |
| 安全配置错误 | Low | High | 遵循安全检查表，验证每一步 |
| 需要回滚 | Low | Low | 保留 Vercel 部署以备快速回滚 |

### 6.1 回滚计划 (Rollback Plan)

如果在迁移后发生严重问题：

1. **立即 (Immediate)** (< 5 分钟): 在 Cloudflare 中恢复 DNS
   - 将 A 记录改回指向 Vercel 的 CNAME
   - 如果需要，禁用代理 (灰云)
2. **传播 (Propagation)**: 5-30 分钟 DNS 全球更新
3. **Vercel**: 部署保持不变，无需操作
