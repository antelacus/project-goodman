## 1. 概述

### 1.1 背景

Project Goodman 目前采用单一管理员模式，所有访问者共享同一个文档空间。随着产品演进，需要：

1. **区分访问者身份**：区分管理员与普通访客
2. **保护用户隐私**：每个用户只能看到自己的文档
3. **控制资源使用**：限制访客的 API 调用频率和存储空间
4. **支持数据提取功能**：修复访客上传文档无法进行数据提取的问题

### 1.2 目标

实现**轻量级用户管理系统**，支持管理员和访客两种角色，为未来完整用户系统奠定基础。

### 1.3 非目标

- ❌ 不实现用户注册功能（涉及法律合规问题）
- ❌ 不实现邮箱验证
- ❌ 不实现 OAuth/SSO 第三方登录
- ❌ 不激活 User 角色（仅定义，预留扩展）

## 3. 用户旅程

### 3.1 管理员登录流程

```
访问任意页面 → 点击登录入口 → 跳转 /login 页面
      ↓
输入用户名/密码 → 验证成功 → 创建 Admin 会话 → 跳转工作台
      ↓
验证失败 → 显示错误 + 暴力破解保护
```

**UI 要点**：
- `/login` 页面：简洁的登录表单（用户名 + 密码）
- 登录入口：在 Navbar 或 Landing Page 提供
- 登录后：重定向到 `/chat` 或原访问页面

### 3.2 访客自动会话流程

```
访客访问网站 → 浏览 Landing Page（无需会话）
      ↓
点击"开始对话"或首次发送消息 → 自动创建 Guest 会话
      ↓
获得临时 Session Token → 开始使用（有速率限制）
      ↓
1小时无活动 → 会话过期 + 临时文件自动清理
```

**UI 要点**：
- 无感创建：访客不需要点击任何"注册"或"登录"按钮
- 明确提示：UI 显示"访客模式"标识和限制说明
- 优雅过期：会话过期时提示用户，可重新开始

### 3.3 访客文档上传流程

```
访客上传文档 → 存储到 Supabase Storage (临时路径)
      ↓
创建数据库记录 (关联 guest_session_id)
      ↓
可进行数据提取和文档问答
      ↓
1小时后 → 自动清理：删除 Storage 文件 + 数据库记录
```

**关键设计**：
- 临时存储路径：`temp/{guest_session_id}/{file_id}`
- 清理机制：定时任务或惰性清理
- 隔离保证：访客只能访问自己 session 的文档

## 4. 功能需求

### 4.1 FR-001: 管理员登录页面

**描述**：创建专用的 `/login` 页面供管理员登录

**验收标准**：
- [ ] 页面路由：`/login`
- [ ] 表单字段：用户名、密码
- [ ] 验证逻辑：调用现有密码验证 API
- [ ] 成功响应：创建会话 + 设置 Cookie + 重定向
- [ ] 失败响应：显示错误信息（模糊化处理）
- [ ] 暴力破解保护：集成现有 `brute-force.ts`
- [ ] 已登录检测：已登录用户访问时重定向到 `/chat`

**UI 设计**：
- 简洁、专业的登录界面
- 与整体设计语言一致
- 响应式适配

### 4.2 FR-002: 访客会话自动创建

**描述**：访客首次交互时自动创建会话

**验收标准**：
- [ ] 触发时机：首次发送聊天消息或上传文档
- [ ] 会话创建：调用 `createSession()` 设置 `role: 'guest'`
- [ ] Cookie 设置：HTTP-only session cookie
- [ ] TTL：1小时（可配置）
- [ ] 活动续期：每次请求刷新 TTL
- [ ] 无感体验：用户无需任何操作

### 4.3 FR-003: 访客速率限制

**描述**：对访客应用更严格的速率限制

**验收标准**：
- [ ] 聊天 API：20 条消息/小时
- [ ] 文档上传：5 个文件/小时
- [ ] 数据提取：10 次/小时
- [ ] 限制提示：达到限制时显示友好提示
- [ ] 限制解除时间：显示剩余等待时间

### 4.4 FR-004: 文档隔离

**描述**：每个用户/访客只能看到自己的业务文档

**验收标准**：
- [ ] 数据库变更：`documents` 表添加 `owner_id` 字段
- [ ] 知识库文档：`doc_category: 'knowledge'` 对所有人可见
- [ ] 业务文档：`doc_category: 'business'` 仅 owner 可见
- [ ] Admin 例外：Admin 可查看所有文档
- [ ] API 过滤：所有文档 API 自动按 owner 过滤

### 4.5 FR-005: 临时文件存储

**描述**：访客上传的文件存储在临时路径，定时清理

**验收标准**：
- [ ] 存储路径：`temp/{guest_session_id}/{file_id}`
- [ ] 数据库记录：`documents.owner_id = guest_session_id`
- [ ] 原始文件存储：存储到 Supabase Storage（修复数据提取问题）
- [ ] 自动清理：1小时后删除 Storage 文件 + 数据库记录
- [ ] 清理机制：**Scheduled Worker (主) + Lazy Cleanup (备)**

**清理机制设计**：
- **主要**：使用 `node-cron` 在 Next.js 进程内运行定时任务，每小时清理过期文件
- **备用**：API 请求时惰性检查并清理（防止定时任务故障时磁盘溢出）
- **选择理由**：VPS 环境支持长运行进程；`node-cron` 比独立 PM2 worker 更简单，且足够应对当前规模

### 4.6 FR-006: 管理员面板

**描述**：提供管理员查看和管理系统状态的界面

**验收标准**：
- [ ] 页面路由：`/admin` 或作为 `/chat` 的侧边栏 tab
- [ ] 会话列表：显示当前活跃的 Guest 会话
- [ ] 会话详情：IP、创建时间、最后活动时间、消息数
- [ ] 强制登出：可以终止指定 Guest 会话
- [ ] 活动日志：显示最近的 Guest 操作记录
- [ ] 存储统计：临时文件占用空间
- [ ] 权限保护：仅 Admin 可访问

### 4.7 FR-007: UI 角色指示

**描述**：在界面上清晰显示当前用户角色和限制

**验收标准**：
- [ ] Navbar 显示：显示当前角色（Admin / 访客）
- [ ] 访客提示：显示速率限制和临时存储说明
- [ ] 登录/登出：Admin 显示登出按钮，访客显示登录入口
- [ ] 限制警告：接近速率限制时显示警告

## 5. 非功能需求

### 5.1 NFR-001: 安全性

| 要求 | 措施 |
|------|------|
| 会话安全 | HTTP-only Cookie, Secure flag, SameSite=Strict |
| 密码安全 | 继续使用 bcrypt 哈希 |
| 暴力破解 | 继续使用现有保护机制 |
| 权限验证 | 每个 API 验证 session 和角色 |

**SameSite 策略说明**：
- 当前使用 `Strict`：最安全，适合内部工具，无外部重定向需求
- **未来注意**：如添加 OAuth 登录或支付回调，需评估是否改为 `Lax`
- `Lax` 允许顶级导航携带 Cookie，对外部链接跳入更友好

### 5.2 NFR-002: 性能

| 要求 | 目标 |
|------|------|
| 会话验证延迟 | < 10ms (Redis) |
| 登录响应时间 | < 500ms |
| 文件清理 | 不影响正常请求 |

### 5.3 NFR-003: 可用性

| 要求 | 措施 |
|------|------|
| Redis 故障 | 降级到内存会话（已有机制） |
| 清理任务故障 | 惰性清理作为备份 |

## 6. 数据模型变更

### 6.1 新增表：users

```sql
CREATE TABLE users (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  username VARCHAR(50) UNIQUE NOT NULL,
  password_hash VARCHAR(255) NOT NULL,
  role VARCHAR(20) NOT NULL DEFAULT 'user',  -- 'admin', 'user', 'guest'
  email VARCHAR(255),
  display_name VARCHAR(100),
  created_at TIMESTAMPTZ DEFAULT NOW(),
  updated_at TIMESTAMPTZ DEFAULT NOW(),
  last_login_at TIMESTAMPTZ,
  is_active BOOLEAN DEFAULT TRUE
);

-- 初始管理员账户（密码从环境变量迁移）
```

### 6.2 修改表：documents

```sql
ALTER TABLE documents
ADD COLUMN owner_id UUID,  -- NULL = 知识库文档（公共）
ADD COLUMN owner_type VARCHAR(20) DEFAULT 'user',  -- 'user', 'guest'
ADD COLUMN expires_at TIMESTAMPTZ;  -- Guest 文档过期时间
```

### 6.3 新增表：guest_sessions (可选)

```sql
-- 可选：如果需要持久化访客会话统计
CREATE TABLE guest_sessions (
  id UUID PRIMARY KEY,
  ip_address INET,
  user_agent TEXT,
  created_at TIMESTAMPTZ DEFAULT NOW(),
  last_activity_at TIMESTAMPTZ DEFAULT NOW(),
  message_count INTEGER DEFAULT 0,
  upload_count INTEGER DEFAULT 0,
  is_active BOOLEAN DEFAULT TRUE
);
```

### 6.4 Redis 数据结构变更

```
现有 Key 结构保持不变：
├── session:{token}              # 扩展 SessionData.userId
├── rate:{endpoint}:{ip}         # 保持不变
├── bruteforce:{ip}:{identifier} # 保持不变

新增 Key：
├── guest:activity:{session_id}  # 访客活动统计
│   └── { messageCount, uploadCount, extractCount, lastActivity }
│   └── TTL: 1 hour
│
└── cleanup:pending              # 待清理的过期 session 列表
    └── Set of session_ids
```

## 11. 风险与缓解

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| 定时清理任务故障 | 存储空间耗尽 | 惰性清理备用 + 存储监控告警 |
| Redis 故障 | 会话丢失 | 降级到内存（已有机制） |
| 访客滥用 | 资源消耗 | 速率限制 + IP 封禁 |
| 管理员密码泄露 | 系统被入侵 | 强制密码复杂度 + 审计日志 |
