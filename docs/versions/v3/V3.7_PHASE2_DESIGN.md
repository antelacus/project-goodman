## 1. 架构概述

### 1.1 当前架构

```
┌──────────────────────────────────────────────────────────┐
│  Navbar (sticky top, 64px height)                        │
├──────────────────────────────────────────────────────────┤
│                                                          │
│              Page Content (full width)                   │
│                                                          │
└──────────────────────────────────────────────────────────┘
```

**问题**:

- 顶部导航占用垂直空间
- 对话型应用需要更多纵向空间
- 移动端导航不够直观

### 1.2 目标架构

```
桌面端 (≥1024px):
┌────────────┬────────────────────────────────────────────┐
│            │                                            │
│  Sidebar   │           Page Content                     │
│  (240px    │           (flex-1)                         │
│   展开)    │                                            │
│            │                                            │
└────────────┴────────────────────────────────────────────┘

桌面端折叠:
┌───────┬─────────────────────────────────────────────────┐
│ Side  │                                                 │
│ bar   │           Page Content                          │
│ (60px │           (flex-1)                              │
│ 仅图  │                                                 │
│ 标)   │                                                 │
└───────┴─────────────────────────────────────────────────┘

移动端 (<768px):
┌──────────────────────────────────────────────────────────┐
│  Mobile Header (Logo + Hamburger)                        │
├──────────────────────────────────────────────────────────┤
│                                                          │
│              Page Content (full width)                   │
│                                                          │
└──────────────────────────────────────────────────────────┘
     │
     └── 汉堡菜单点击 → Sidebar Overlay 从左滑出
```

### 3.4 交互行为

**折叠/展开**:

- 点击折叠按钮切换状态
- 状态保存到 localStorage (`sidebar-collapsed`)
- 使用 CSS transition 实现平滑动画

**移动端**:

- 点击汉堡菜单，Sidebar 从左侧滑入
- 显示半透明遮罩层
- 点击遮罩或关闭按钮关闭
- ESC 键关闭

## 4. 响应式设计

### 4.1 断点策略

| 断点 | 宽度 | 布局 |
|------|------|------|
| `mobile` | < 768px | Header + Overlay Sidebar |
| `tablet` | 768px - 1023px | Sidebar (默认折叠) |
| `desktop` | ≥ 1024px | Sidebar (默认展开) |

### 4.2 布局切换

```typescript
// 伪代码表示响应式逻辑
if (viewport < 768px) {
  // 移动端: Header + Overlay
  showMobileHeader = true
  showSidebar = false
  sidebarMode = 'overlay'
} else if (viewport < 1024px) {
  // 平板: 常驻折叠 Sidebar
  showMobileHeader = false
  showSidebar = true
  defaultCollapsed = true
} else {
  // 桌面: 常驻展开 Sidebar
  showMobileHeader = false
  showSidebar = true
  defaultCollapsed = false
}
```

### 4.3 内容区适配

**ChatWorkspace 高度计算变更**:

```css
/* 当前 */
height: calc(100vh - 64px);  /* 减去 Navbar 高度 */

/* V3.7 桌面端 */
height: 100vh;  /* 全屏高度 */

/* V3.7 移动端 */
height: calc(100vh - 56px);  /* 减去 MobileHeader 高度 */
```

## 6. 页面路由变更

### 6.1 页面布局归属

|       页面       | 显示侧边栏 | 显示 MobileHeader |
|-----------------|----------|-------------------|
| `/` (Landing)   | ❌ 否     | ❌ 否             |
| `/chat`         | ✅ 是     | ✅ 是 (移动端)     |
| `/documents`    | ✅ 是     | ✅ 是 (移动端)     |
| `/help`         | ✅ 是     | ✅ 是 (移动端)     |
| `/about`        | ✅ 是     | ✅ 是 (移动端)     |

### 6.2 布局结构方案

**方案: Route Group 布局**

```
src/app/
├── (landing)/
│   └── page.tsx        # Landing 页 (无侧边栏)
├── (workspace)/
│   ├── layout.tsx      # 带侧边栏的布局
│   ├── chat/
│   │   └── page.tsx
│   ├── documents/
│   │   └── page.tsx
│   ├── help/
│   │   └── page.tsx
│   └── about/
│       └── page.tsx
└── layout.tsx          # 根布局
```

**优点**:

- 清晰的布局分离
- Landing 页完全独立
- 便于后续扩展

## 7. 特殊功能设计

### 7.1 新建对话按钮

**行为**:

1. 点击按钮
2. 调用 ChatWorkspace 的 reset 方法
3. 清空消息列表
4. 生成新的 sessionId
5. 如果在移动端，关闭侧边栏

**实现**:

- 通过 Context 或事件总线传递 reset 事件
- 或使用 URL 参数触发 (如 `/chat?new=true`)

### 7.2 快捷工具 - 财务信息提取

**行为**:

1. 点击侧边栏中的"财务信息提取"
2. 打开上传模态框 (复用现有 ExtractionResultModal 的上传部分)
3. 用户选择/上传文件
4. 触发提取流程
5. 在聊天中显示结果

**实现**:

- 使用 React Portal 渲染模态框
- 复用 ChatInput 中的文件上传逻辑

### 7.3 帮助页面更新

**变更**:

- 移除当前的教程折叠面板
- 使用 README.md 内容
- Markdown 渲染

**实现方案**:

1. 在构建时将 README.md 内容导入
2. 使用 react-markdown 渲染
3. 保持与聊天消息相同的 Markdown 样式
