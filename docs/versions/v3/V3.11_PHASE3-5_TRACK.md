### 6.1 任务 5.1: 创建统一提取结果类型

**变更文件**: `src/lib/extraction/index.ts`

**新增类型**:
- `FinancialStatementContent` - 财务报表内容类型 (`Record<string, number | null | undefined>`)
- `FinancialPeriodData` - 单期财务数据接口 (`{ year, period, content }`)
- `FinancialStatementType` - 财务报表类型联合 (`'balance_sheet' | 'income_statement' | 'cash_flow'`)
- `FinancialExtractionWithType` - 统一提取结果接口 (`{ type, data }`)

---

### 6.2 任务 5.2: 更新 upload-database-document

**变更文件**: `src/app/api/admin/upload-database-document/route.ts`

**修复内容**:
1. **导入新类型**: `FinancialExtractionWithType`, `FinancialStatementType`, `FinancialStatementContent`
2. **导入验证类型**: `StandardBalanceSheet`, `StandardIncomeStatement`, `StandardCashFlow`
3. **修复 aiResult 类型**: 使用 `FinancialExtractionWithType` 替代隐式 `any`
4. **修复 column extraction**: 构造符合类型的结果对象而非 `(aiResult as any).type = documentType`
5. **修复 validation calls**: 使用 `as unknown as StandardBalanceSheet` 替代 `as any`
6. **修复 validationReports 类型**: 使用显式类型注解替代 `any[]`

**移除的 `as any`**:
- `(aiResult as any).type = documentType` → 使用类型安全的对象构造
- `(aiResult as any).type === 'balance_sheet'` → 使用 `aiResult.type === 'balance_sheet'`
- `(aiResult as any).type === 'income_statement'` → 使用 `aiResult.type === 'income_statement'`
- `item.content as any` (3 处) → 使用 `as unknown as StandardXxx`

**XLSX**:
```typescript
// REASON: XLSX.utils.sheet_to_json() 返回 unknown[]。
// 这是系统边界，外部未类型化数据进入的位置。
// 为每个单元格添加运行时验证会产生过多开销。
```

```typescript
// REASON: 访问 Zod 内部 _def 属性进行运行时 schema 内省。
// 这是将 Zod schemas 转换为 OpenAI 函数参数所必需的。
// 此功能不存在公共 API。
```

**JSONB**:
```typescript
// REASON: 数据库 JSONB 列返回泛型 Json 类型，
// 但结构在插入时已验证为 DbToolCall[]。
// 运行时验证在此处无收益。
```
