## 1. 设计目标

### 1.1 核心目标

基于现有 V3.2 安全基础设施，实现轻量级用户管理系统，支持管理员和访客两种角色。

**关键原则**：

- 最大限度复用现有代码（Session、Brute Force、Audit Log）
- 最小化数据库变更
- 遵循现有代码规范和目录结构
- 为未来 User 角色预留扩展点

### 1.2 非目标

- ❌ 不实现用户注册流程
- ❌ 不实现邮箱验证
- ❌ 不激活 User 角色
- ❌ 不添加 OAuth/SSO

## 3. 数据库设计

### 3.1 新增表: users

```sql
-- 用户表 (当前仅存储 Admin，未来可扩展)
CREATE TABLE users (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    username VARCHAR(50) UNIQUE NOT NULL,
    password_hash VARCHAR(255) NOT NULL,
    role VARCHAR(20) NOT NULL DEFAULT 'user'
        CHECK (role IN ('admin', 'user', 'guest')),
    display_name VARCHAR(100),
    email VARCHAR(255),
    is_active BOOLEAN DEFAULT TRUE,
    created_at TIMESTAMPTZ DEFAULT NOW(),
    updated_at TIMESTAMPTZ DEFAULT NOW(),
    last_login_at TIMESTAMPTZ
);

-- 索引
CREATE INDEX idx_users_username ON users(username);
CREATE INDEX idx_users_role ON users(role);

-- 初始管理员账户 (密码从环境变量迁移)
-- 在应用启动时通过迁移脚本创建
```

**设计说明**：

| 字段 | 说明 |
|------|------|
| `id` | UUID，便于分布式场景 |
| `username` | 登录用户名，唯一 |
| `password_hash` | bcrypt 哈希，复用现有 `password.ts` |
| `role` | 角色：admin/user/guest |
| `display_name` | 显示名称（可选） |
| `email` | 邮箱（预留，当前不用） |
| `is_active` | 账户状态 |

### 3.2 修改表: documents

```sql
-- 添加文档所有权字段
ALTER TABLE documents
ADD COLUMN owner_id UUID,                    -- 所有者 ID (users.id 或 session_id)
ADD COLUMN owner_type VARCHAR(20)
    DEFAULT 'system'
    CHECK (owner_type IN ('system', 'admin', 'user', 'guest')),
ADD COLUMN expires_at TIMESTAMPTZ;           -- Guest 文档过期时间

-- 索引
CREATE INDEX idx_documents_owner ON documents(owner_id, owner_type);
CREATE INDEX idx_documents_expires ON documents(expires_at)
    WHERE expires_at IS NOT NULL;

-- 更新现有文档为 system 所有
UPDATE documents SET owner_type = 'system' WHERE owner_type IS NULL;
```

**所有权模型**：

| owner_type | owner_id | 说明 |
|------------|----------|------|
| `system` | NULL | 知识库文档，所有人可见 |
| `admin` | users.id | Admin 上传的业务文档 |
| `user` | users.id | User 上传的业务文档（预留） |
| `guest` | session_id | Guest 临时文档，1小时后过期 |

### 3.3 新增表: guest_activity (可选)

```sql
-- 访客活动统计 (持久化，用于 Admin 面板)
CREATE TABLE guest_activity (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    session_id UUID NOT NULL,
    ip_address INET,
    user_agent TEXT,
    message_count INTEGER DEFAULT 0,
    upload_count INTEGER DEFAULT 0,
    extract_count INTEGER DEFAULT 0,
    created_at TIMESTAMPTZ DEFAULT NOW(),
    last_activity_at TIMESTAMPTZ DEFAULT NOW(),
    expired_at TIMESTAMPTZ                   -- 标记已过期
);

-- 索引
CREATE INDEX idx_guest_activity_session ON guest_activity(session_id);
CREATE INDEX idx_guest_activity_created ON guest_activity(created_at);
```

**设计决策**：此表为可选，仅在需要持久化访客统计时创建。Redis 中的实时数据足以支持大多数场景。

### 3.4 Redis 数据结构

```
现有 Key 保持不变:
├── session:{token}              # 会话数据 (扩展 userId)
├── rate:{endpoint}:{ip}         # 速率限制
├── bruteforce:{ip}:{identifier} # 暴力破解

新增/扩展 Key:
├── session:{token}
│   └── {
│         token, createdAt, expiresAt,
│         ip, userAgent,
│         userId: UUID | null,      # Admin: users.id, Guest: null
│         role: 'admin' | 'guest',  # 角色
│         sessionId: UUID           # 用于 Guest 文档关联
│       }
│   └── TTL: Admin 24h, Guest 1h
│
├── guest:rate:{session_id}:{action}  # Guest 速率限制
│   └── { count, windowStart }
│   └── TTL: 1 hour
│
└── cleanup:pending                    # 待清理的过期 session
    └── Set of session_ids
    └── 无 TTL (由清理任务管理)
```

## 4. API 设计

### 4.1 认证 API

#### POST /api/auth/login

**描述**：管理员登录

**请求**：
```typescript
{
  username: string,  // 用户名
  password: string   // 密码
}
```

**响应**：
```typescript
// 成功 (200)
{
  success: true,
  user: {
    id: string,
    username: string,
    displayName: string,
    role: 'admin'
  },
  expiresAt: number  // Unix timestamp (ms)
}

// 失败 (401)
{
  success: false,
  error: '用户名或密码错误'
}

// 锁定 (429)
{
  success: false,
  error: '账号已锁定，请稍后重试',
  retryAfter: number  // 秒
}
```

**逻辑流程**：
1. 验证输入 (Zod)
2. 检查暴力破解状态
3. 查询 users 表
4. 验证密码 (bcrypt)
5. 创建 Redis 会话 (role: 'admin', userId: user.id)
6. 设置 HTTP-only Cookie
7. 记录审计日志

**请求**：无 body，使用 Cookie 中的 session token

**响应**：

**逻辑**：

2. 销毁 Redis 会话

## 5. 会话管理设计

### 5.1 会话类型

| 类型 | TTL | 创建方式 | Cookie |
|------|-----|----------|--------|
| Admin | 24小时 | /login 登录 | session={token}; HttpOnly; Secure; SameSite=Strict |
| Guest | 1小时 | 首次交互自动创建 | session={token}; HttpOnly; Secure; SameSite=Strict |

### 5.2 Guest 会话自动创建

**触发时机**：

1. 首次发送聊天消息 (`/api/chat/*`)
2. 首次上传文档 (`/api/documents/upload-temp`)
3. 首次使用数据提取 (`/api/quick-actions/extract`)

**实现位置**：`src/middleware.ts` 或各 API Route

**推荐方案**：在 API Route 中按需创建（更精确控制）

```typescript
// src/lib/security/guest-session.ts

export async function ensureGuestSession(
  request: NextRequest
): Promise<{ session: SessionData; response?: NextResponse }> {
  const token = request.cookies.get(COOKIE_NAME)?.value;

  if (token) {
    const session = await verifySession(token);
    if (session) {
      // 续期活跃会话
      await renewSession(token);
      return { session };
    }
  }

  // 创建新的 Guest 会话
  const ip = getClientIP(request);
  const userAgent = request.headers.get('user-agent') || '';
  const session = await createGuestSession(ip, userAgent);

  // 返回需要设置 Cookie 的响应
  const response = new NextResponse();
  response.cookies.set(COOKIE_NAME, session.token, {
    ...COOKIE_OPTIONS,
    maxAge: 60 * 60  // 1 hour for guest
  });

  return { session, response };
}
```

### 5.3 会话续期策略

```typescript
// Admin: 每次请求续期 (sliding window)
```

## 7. 定时清理设计

### 7.1 清理任务架构

```
┌─────────────────────────────────────────────────────────────┐
│                     清理任务架构                              │
├─────────────────────────────────────────────────────────────┤
│                                                              │
│  ┌─────────────────────────────────────┐                    │
│  │ node-cron (Next.js 进程内)          │                    │
│  │   Schedule: '0 * * * *' (每小时)    │                    │
│  └────────────────┬────────────────────┘                    │
│                   ↓                                          │

│  │ cleanupExpiredGuests()              │                    │
│  │   1. 查询过期文档                    │                    │
│  │   2. 删除 Supabase Storage 文件     │                    │
│  │   3. 删除数据库记录                  │                    │
│  │   4. 清理 Redis 会话                 │                    │
│  │   5. 记录审计日志                    │                    │
│  └─────────────────────────────────────┘                    │
│                                                              │
│  备用: 惰性清理                                              │
│  ┌─────────────────────────────────────┐                    │
│  │ API 请求时检查                       │                    │
│  │   - 查询自己的过期文档               │                    │
│  │   - 顺便清理                         │                    │
│  └─────────────────────────────────────┘                    │
│                                                              │
└─────────────────────────────────────────────────────────────┘
```

### 7.2 实现代码

```typescript
// src/lib/cleanup/guest-cleanup.ts

import cron from 'node-cron';
import { supabase } from '@/lib/database/supabase';
import { deleteStorageFile } from '@/lib/documents/storage';
import { logSecurityEvent } from '@/lib/security/audit-logger';

export function startCleanupScheduler() {
  // 每小时执行一次 (minute 0)
  cron.schedule('0 * * * *', async () => {
    await cleanupExpiredGuests();
  });

  console.log('[Cleanup] Scheduled guest cleanup task (hourly)');
}

async function cleanupExpiredGuests() {
  const now = new Date().toISOString();

  // 1. 查询过期文档
  const { data: expiredDocs, error } = await supabase
    .from('documents')
    .select('id, file_url, owner_id')
    .eq('owner_type', 'guest')
    .lt('expires_at', now);

  if (error || !expiredDocs?.length) {
    return;
  }

  console.log(`[Cleanup] Found ${expiredDocs.length} expired guest documents`);

  // 2. 删除每个文档
  for (const doc of expiredDocs) {
    try {
      // 删除 Storage 文件
      if (doc.file_url) {
        await deleteStorageFile(doc.file_url);
      }

      // 删除数据库记录 (级联删除 chunks)
      await supabase.from('documents').delete().eq('id', doc.id);

    } catch (err) {
      console.error(`[Cleanup] Failed to delete document ${doc.id}:`, err);
    }
  }

  // 3. 记录审计日志
  logSecurityEvent('cleanup_completed', '127.0.0.1', 'system', {
    documentsDeleted: expiredDocs.length,
    sessionsCleaned: [...new Set(expiredDocs.map(d => d.owner_id))].length
  });
}
```

### 7.4 惰性清理备份

```typescript
// src/lib/cleanup/lazy-cleanup.ts

export async function lazyCleanupForSession(sessionId: string) {
  const now = new Date().toISOString();

  // 删除该 session 的过期文档
  const { data: expiredDocs } = await supabase
    .from('documents')
    .select('id, file_url')
    .eq('owner_id', sessionId)
    .eq('owner_type', 'guest')
    .lt('expires_at', now);

  if (expiredDocs?.length) {
    for (const doc of expiredDocs) {
      if (doc.file_url) {
        await deleteStorageFile(doc.file_url);
      }
      await supabase.from('documents').delete().eq('id', doc.id);
    }
  }
}
```

## 10. 安全考虑

### 10.1 认证安全

| 威胁 | 缓解措施 |
|------|----------|
| 暴力破解 | 现有 brute-force 保护 (5次失败锁定15分钟) |
| 会话劫持 | HTTP-only + Secure + SameSite=Strict |
| CSRF | SameSite=Strict (当前足够，无外部重定向) |
| 会话固定 | 登录时生成新 token |

### 10.2 访问控制

```typescript
// 权限检查中间件模式
async function requireAdmin(request: NextRequest) {
  const session = await getSession(request);
  if (!session || session.role !== 'admin') {
    return NextResponse.json({ error: 'Forbidden' }, { status: 403 });
  }
  return null;  // 继续处理
}

async function requireAuthenticated(request: NextRequest) {
  const session = await getSession(request);
  if (!session) {
    return NextResponse.json({ error: 'Unauthorized' }, { status: 401 });
  }
  return null;
}
```

### 10.3 数据隔离

```sql
-- RLS 策略 (可选，当前使用应用层过滤)
ALTER TABLE documents ENABLE ROW LEVEL SECURITY;

CREATE POLICY "Users can view own documents"
ON documents FOR SELECT
USING (
  owner_type = 'system'  -- 知识库对所有人可见
  OR owner_id = auth.uid()  -- 自己的文档
  OR EXISTS (SELECT 1 FROM users WHERE id = auth.uid() AND role = 'admin')  -- Admin 例外
);
```

**当前方案**：使用应用层过滤（API 中添加 WHERE 条件），因为：
1. Guest 没有 Supabase auth.uid()
2. 更灵活的控制
3. RLS 可作为未来增强
