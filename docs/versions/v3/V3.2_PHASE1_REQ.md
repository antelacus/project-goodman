## 1. 概述

### 1.1 背景

V2 阶段 6 安全审计识别了多项安全改进需求。这些改进对于生产环境的安全运行至关重要，但因超出 MVP 范围而推迟到 V3.2 实施。

### 1.2 目标

实施全面的安全增强措施，将系统从"MVP 演示级别"提升到"生产就绪级别"。

### 1.3 范围

本版本涵盖所有优先级的安全增强：

| 优先级 | 范围 | 说明 |
|--------|------|------|
| P1 关键 | 服务端速率限制、输入验证、错误脱敏 | 生产必需 |
| P2 高 | 密码哈希、会话令牌、暴力破解防护、路径验证 | 安全加固 |
| P3 中 | 安全头、文件验证、审计日志 | 深度防御 |

### 1.4 前置条件

- ✅ V3.0 VPS 迁移完成
- ✅ V3.1 LangGraph 预备重构完成
- ⏳ Redis 安装 (本版本实施)

## 3. 需求规格

### 3.1 P1 关键需求

#### 3.1.1 REQ-001: 服务端速率限制

**描述**: 在服务端实施 API 速率限制，防止滥用和 DoS 攻击。

**功能需求**:

- FR-001.1: 基于 IP 地址的速率限制
- FR-001.2: 基于端点的差异化限制（如 AI 端点更严格）
- FR-001.3: 超限时返回 HTTP 429 状态码
- FR-001.4: 响应头包含限制信息 (X-RateLimit-*)

**限制策略**:

| 端点类别 | 限制 | 窗口 | 说明 |
|----------|------|------|------|
| AI 端点 (chat, analysis) | 20 次 | 1 分钟 | OpenAI 成本控制 |
| 数据端点 (query, list) | 60 次 | 1 分钟 | 正常使用模式 |
| 认证端点 (admin) | 5 次 | 1 分钟 | 暴力破解防护 |
| 静态资源 | 无限制 | - | 缓存处理 |

**技术要求**:

- 使用 Redis 存储计数器（支持分布式、持久化）
- 滑动窗口算法（比固定窗口更平滑）
- 支持白名单（本地开发、健康检查）

#### 3.1.2 REQ-002: 输入长度验证

**描述**: 验证所有 API 输入的长度，防止过大请求。

**功能需求**:

- FR-002.1: 请求体总大小限制
- FR-002.2: 字段级长度验证
- FR-002.3: 超限时返回 HTTP 413 状态码

**长度限制**:

| 字段类型 | 最大长度 | 说明 |
|----------|----------|------|
| 用户问题 (question) | 2,000 字符 | 合理的问题长度 |
| 对话历史 (messages) | 10 条 / 20,000 字符 | 上下文窗口限制 |
| 文档 ID 列表 | 20 个 | 单次查询范围 |
| 管理员密码 | 128 字符 | 安全且合理 |
| 请求体总大小 | 1 MB | Next.js 默认 |

**技术要求**:

- 在 Zod schema 中添加 `.max()` 验证
- 在 API 路由层统一验证
- 返回用户友好的错误信息

#### 3.1.3 REQ-003: 错误信息脱敏

**描述**: 生产环境中不向客户端暴露详细错误信息。

**功能需求**:

- FR-003.1: 区分开发环境和生产环境
- FR-003.2: 生产环境返回通用错误信息
- FR-003.3: 详细错误记录到服务端日志

**错误响应格式**:

```typescript
// 开发环境
{
  "error": "处理请求时出错",
  "details": "Error: ECONNREFUSED...",
  "stack": "at processTicksAndRejections..."
}

// 生产环境
{
  "error": "处理请求时出错，请稍后重试",
  "requestId": "req_abc123"  // 用于日志关联
}
```

**技术要求**:

- 基于 `NODE_ENV` 环境变量判断
- 生成请求 ID 用于日志关联
- 敏感信息（API 密钥、内部路径）永不暴露

### 3.2 P2 高优先级需求

#### 3.2.1 REQ-004: 密码哈希存储

**描述**: 使用 bcrypt 哈希存储管理员密码。

**功能需求**:

- FR-004.1: 密码使用 bcrypt 哈希后存储
- FR-004.2: 验证时比较哈希值而非明文
- FR-004.3: 支持迁移现有明文密码

**技术要求**:

- bcrypt cost factor: 12（安全与性能平衡）
- 密码验证时使用 `bcrypt.compare()` 时间常量比较
- 迁移策略：首次验证成功后自动升级

#### 3.2.2 REQ-005: 会话令牌认证

**描述**: 用会话令牌替代每次请求的密码验证。

**功能需求**:

- FR-005.1: 登录成功后发放会话令牌
- FR-005.2: 后续请求使用令牌而非密码
- FR-005.3: 令牌有过期时间
- FR-005.4: 支持手动登出（令牌失效）

**会话规格**:

| 属性 | 值 | 说明 |
|------|---|------|
| 令牌格式 | 随机 UUID v4 | 不可预测 |
| 有效期 | 24 小时 | 平衡安全与便利 |
| 存储位置 | Redis | 支持分布式 |
| 传输方式 | HTTP-only Cookie | 防止 XSS 窃取 |

**技术要求**:

- Redis 存储会话数据
- Cookie 设置: `HttpOnly`, `Secure`, `SameSite=Strict`
- 支持会话续期（活跃用户自动延长）

#### 3.2.3 REQ-006: 暴力破解防护

**描述**: 防止密码暴力破解攻击。

**功能需求**:

- FR-006.1: 连续失败后实施延迟
- FR-006.2: 达到阈值后临时锁定
- FR-006.3: 锁定后通知（日志记录）

**防护策略**:

| 失败次数 | 响应 |
|----------|------|
| 1-3 次 | 正常响应 |
| 4-5 次 | 延迟 2 秒响应 |
| 6+ 次 | 锁定 15 分钟 |

**技术要求**:

- 基于 IP + 用户名组合计数
- Redis 存储失败计数（TTL 15 分钟）
- 成功登录后重置计数

#### 3.2.4 REQ-007: 文件路径验证

**描述**: 防止路径遍历攻击。

**功能需求**:

- FR-007.1: 验证文件路径不包含 `..`
- FR-007.2: 验证路径在允许的目录内
- FR-007.3: 规范化路径后再验证

**技术要求**:

- 使用 `path.resolve()` 规范化路径
- 检查规范化后路径是否以允许目录开头
- 拒绝包含空字节的路径

### 3.3 P3 中优先级需求

#### 3.3.1 REQ-008: 安全响应头

**描述**: 添加安全相关的 HTTP 响应头。

**功能需求**:

- FR-008.1: 设置 CSP (Content-Security-Policy)
- FR-008.2: 设置 X-Frame-Options
- FR-008.3: 设置 X-Content-Type-Options
- FR-008.4: 设置 Referrer-Policy
- FR-008.5: 设置 Permissions-Policy

**安全头配置**:

| 头部 | 值 | 作用 |
|------|---|------|
| `X-Frame-Options` | `DENY` | 防止点击劫持 |
| `X-Content-Type-Options` | `nosniff` | 防止 MIME 类型嗅探 |
| `Referrer-Policy` | `strict-origin-when-cross-origin` | 控制 Referer 泄露 |
| `X-XSS-Protection` | `1; mode=block` | 浏览器 XSS 过滤器 |
| `Content-Security-Policy` | 见下文 | 防止 XSS、注入 |

**CSP 策略** (初步):

```
default-src 'self';
script-src 'self' 'unsafe-inline' 'unsafe-eval';  // Next.js 需要
style-src 'self' 'unsafe-inline';                  // Tailwind 需要
img-src 'self' data: https:;
connect-src 'self' https://api.openai.com https://*.supabase.co;
```

**技术要求**:

- 在 `next.config.js` 中配置
- 或使用 Next.js Middleware 添加

#### 3.3.2 REQ-009: 文件内容验证

**描述**: 验证上传文件的实际内容类型。

**功能需求**:

- FR-009.1: 检查文件魔数 (magic number)
- FR-009.2: 验证实际类型与声明类型匹配
- FR-009.3: 拒绝不支持的文件类型

**支持的文件类型**:

| 类型 | 扩展名 | 魔数 (Magic Number) |
|------|--------|---------------------|
| PDF | .pdf | `%PDF` (0x25504446) |
| XLSX | .xlsx | `PK` (0x504B) - ZIP 格式 |
| Markdown | .md | 无（文本文件） |

**技术要求**:

- 读取文件前 N 字节检查魔数
- 文本文件使用编码检测
- 记录被拒绝的上传尝试

#### 3.3.3 REQ-010: 审计日志

**描述**: 记录安全相关操作以支持事后分析。

**功能需求**:

- FR-010.1: 记录管理员登录/登出
- FR-010.2: 记录数据修改操作
- FR-010.3: 记录安全事件（失败登录、速率限制触发）
- FR-010.4: 日志包含时间戳、IP、用户代理

**审计日志格式**:

```typescript
interface AuditLog {
  timestamp: string;      // ISO 8601
  eventType: string;      // 'admin_login' | 'admin_logout' | 'data_modify' | 'security_event'
  action: string;         // 'login_success' | 'login_failed' | 'document_delete' | ...
  ip: string;
  userAgent: string;
  userId?: string;
  details?: object;       // 事件特定数据
}
```

**技术要求**:

- 初期写入文件日志（`logs/audit.log`）
- 使用结构化 JSON 格式
- 日志轮转（按日期或大小）
- 未来可迁移到专用日志服务

## 4. 技术方案概要

### 4.1 基础设施

#### 4.1.1 Redis 安装

**用途**:

- 服务端速率限制计数器
- 会话令牌存储
- 暴力破解防护计数
- (未来) 对话记忆持久化

**安装方案**:

- 在 VPS 本地安装 Redis
- 使用 Docker 容器运行
- 通过 127.0.0.1:6379 连接（无需外部暴露）

**配置要点**:

- 最大内存: 256MB（足够当前用量）
- 持久化: RDB 快照（每 5 分钟）
- 密码保护: 启用 `requirepass`

### 4.2 实现架构

```
┌─────────────────────────────────────────────────────────────────┐
│                         请求流程                                 │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│   请求 ─→ [nginx] ─→ [Next.js Middleware] ─→ [API Route]       │
│              │              │                    │               │
│              │              ├─ 安全头注入        ├─ 输入验证     │
│              │              ├─ 速率限制检查      ├─ 会话验证     │
│              │              └─ IP 提取           └─ 业务逻辑     │
│              │                    │                              │
│              │                    ↓                              │
│              │              [Redis]                              │
│              │              ├─ rate:ip:{ip}:{endpoint}          │
│              │              ├─ session:{token}                  │
│              │              └─ bruteforce:{ip}:{user}           │
│              │                                                   │
│              └─ access.log (nginx 访问日志)                      │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 4.3 技术选型

| 组件 | 选择 | 理由 |
|------|------|------|
| 速率限制 | 自实现 + Redis | 简单需求无需引入 rate-limiter-flexible 等库 |
| 密码哈希 | bcryptjs | 已在项目中，JavaScript 实现 |
| 会话管理 | 自实现 + Redis | 简单需求无需引入 express-session |
| 安全头 | Next.js Config | 原生支持，无需中间件 |
| 日志 | 自实现 JSON 日志 | 简单需求无需 winston/pino |

## 5. 成功标准

### 5.1 功能验收标准

| 需求 | 验收标准 |
|------|----------|
| REQ-001 | 超过速率限制返回 429，包含正确的 X-RateLimit-* 头 |
| REQ-002 | 超长输入返回 413，错误信息指明哪个字段超限 |
| REQ-003 | 生产环境错误响应不包含堆栈跟踪和内部路径 |
| REQ-004 | 数据库中密码存储为 bcrypt 哈希格式 |
| REQ-005 | 登录后使用令牌访问管理功能，密码不再传输 |
| REQ-006 | 6 次失败登录后账户锁定 15 分钟 |
| REQ-007 | 包含 `../` 的路径请求被拒绝 |
| REQ-008 | 响应包含所有指定的安全头 |
| REQ-009 | 扩展名与内容不匹配的文件上传被拒绝 |
| REQ-010 | 审计日志文件记录所有管理操作 |

### 5.2 安全测试标准

| 测试类型 | 验收标准 |
|----------|----------|
| 速率限制绕过 | 无法通过更换 User-Agent 或伪造 X-Forwarded-For 绕过 |
| SQL 注入 | 现有防护保持有效 |
| XSS | CSP 阻止内联脚本执行（测试环境验证） |
| 暴力破解 | 自动化脚本在 6 次尝试后被阻止 |

### 5.3 性能标准

| 指标 | 标准 | 说明 |
|------|------|------|
| 速率限制检查延迟 | < 5ms | Redis 本地访问 |
| 会话验证延迟 | < 5ms | Redis 本地访问 |
| 密码验证延迟 | < 500ms | bcrypt cost=12 |
| 整体 API 延迟增加 | < 20ms | 安全检查总开销 |

## 8. 用户管理扩展性设计

> **备注**: 本版本暂不实现完整的用户管理系统，但在架构设计上预留扩展点，确保未来添加用户管理时只需"扩展"而非"重构"。

### 8.1 背景

2025-12-16 讨论确认：

- 短期内无多用户业务需求
- 完整用户管理系统延迟至 V3.7 实现
- V3.2 需为未来扩展做好准备

### 8.2 扩展性设计要点

#### 8.2.1 会话令牌 (REQ-005)

**当前实现**: 单一管理员会话

**预留扩展点**:

```typescript
interface SessionData {
  token: string;
  createdAt: string;
  expiresAt: string;
  ip: string;
  // 未来扩展字段（当前为空/可选）
  userId?: string;     // 用户 ID
  role?: string;       // 角色 (admin | user | guest)
}
```

**未来扩展**: 添加用户注册/登录时，无需修改会话机制，只需填充 `userId` 和 `role` 字段。

#### 8.2.2 速率限制 (REQ-001)

**当前实现**: 基于 IP 地址

**预留扩展点**:

```typescript
// Redis Key 结构设计
// 当前: rate:{ip}:{endpoint}
// 未来: rate:{userId}:{endpoint} 或 rate:{ip}:{userId}:{endpoint}
```

**未来扩展**: 支持用户级别的差异化限制（如 VIP 用户更高限额）。

#### 8.2.3 审计日志 (REQ-010)

**当前实现**: `userId` 字段已在接口中定义为可选

**预留扩展点**: 在 `AuditLog` 接口中，`userId` 已预留，当前记录为空或 `admin`。

**未来扩展**: 用户系统就绪后，自动记录实际用户 ID。

### 8.3 未来 V3.7 用户管理范围（预览）

| 功能 | 说明 |
|------|------|
| 用户注册/登录 | 用户名/密码认证 |
| 角色权限 | admin / user / guest 区分 |
| 用户资料 | 基本信息管理 |
| 权限控制 | 基于角色的功能访问控制 |

### B. 术语表

| 术语 | 定义 |
|------|------|
| 速率限制 (Rate Limiting) | 限制单位时间内的请求数量 |
| 滑动窗口 (Sliding Window) | 速率限制算法，使用移动时间窗口计数 |
| bcrypt | 自适应哈希函数，专为密码存储设计 |
| CSP | Content Security Policy，内容安全策略 |
| 魔数 (Magic Number) | 文件开头的固定字节序列，标识文件类型 |
