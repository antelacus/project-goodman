## 1. 背景与动机

### 1.1 问题陈述

当前系统中，AI Agent 仅向用户展示最终结果，而不显示推理和计算过程。对于财务工作而言，这存在严重问题：

| 问题 | 影响 |
|------|------|
| **不可验证** | 用户无法核实计算是否正确 |
| **缺乏信任** | 结果看起来像"黑箱"输出 |
| **无法审计** | 不满足财务工作的审计追踪要求 |
| **数据来源不明** | 用户不知道数据取自哪份文件 |

### 1.2 目标用户

- **财务人员**：需要验证 Agent 计算结果的准确性
- **审计人员**：需要追溯数据来源和计算步骤
- **管理层**：需要确信 AI 输出基于可靠数据

### 1.3 核心价值

**建立信任**：通过透明化 Agent 工作过程，让用户能够手动验证每一步操作，从而信任 AI 输出的结果。

## 2. 用户故事

### US-001: 查看计算过程
**作为** 财务人员
**我希望** 看到 Agent 计算财务指标的完整过程
**以便** 我可以验证计算逻辑和使用的数据是否正确

**验收标准**:
- [ ] 每个 Agent 响应都附带可展开的过程日志
- [ ] 过程日志默认折叠，不干扰主要内容
- [ ] 点击可展开查看详细步骤

### US-002: 追溯数据来源
**作为** 财务人员
**我希望** 看到 Agent 使用的数据来自哪份文档
**以便** 我可以核对原始数据是否被正确提取

**验收标准**:
- [ ] 数据来源显示为可点击链接
- [ ] 点击链接可跳转到原始文档或文档详情页
- [ ] 显示具体的数据值和来源文档名称

### US-003: 理解 Agent 推理
**作为** 用户
**我希望** 了解 Agent 是如何理解我的问题的
**以便** 我可以判断 Agent 是否正确理解了我的意图

**验收标准**:
- [ ] 显示 Agent 的意图识别结果
- [ ] 显示 Agent 选择使用的工具及原因

### US-004: 查看工具调用详情
**作为** 高级用户
**我希望** 看到 Agent 调用了哪些工具及其参数
**以便** 我可以理解系统的工作方式并排查问题

**验收标准**:
- [ ] 显示工具名称和调用参数
- [ ] 显示工具返回的原始结果
- [ ] 显示计算公式和数值

## 3. 功能需求

### 3.1 过程事件类型

系统需要捕获并展示以下类型的事件：

| 事件类型 | 图标 | 说明 | 示例 |
|----------|------|------|------|
| `thinking` | 🤔 | Agent 推理/思考 | "用户想计算流动比率" |
| `tool_call` | 🔧 | 工具调用（开始） | "调用 current_ratio 工具" |
| `tool_result` | ✅ | 工具返回结果 | "流动比率 = 2.15" |
| `data_fetch` | 📄 | 数据获取 | "从2024年资产负债表获取数据" |
| `calculation` | 📊 | 计算步骤 | "1,234,567 ÷ 573,891 = 2.15" |
| `error` | ❌ | 错误信息 | "未找到所需数据" |

### 3.2 事件数据结构

每个事件应包含以下字段：

```typescript
interface ProcessEvent {
  id: string;                    // 唯一标识（UUID v4 格式，用于 React 列表渲染）
  timestamp: number;             // 时间戳
  type: EventType;               // 事件类型
  content: string;               // 用户友好的事件描述（已人性化处理）
  details?: Record<string, unknown>;  // 详细数据（可选，用于展开查看）
  sourceReference?: SourceReference;  // 数据来源引用（可选）
}

type EventType = 'thinking' | 'tool_call' | 'tool_result' | 'data_fetch' | 'calculation' | 'error';

interface SourceReference {
  documentId: string;            // 文档 ID
  documentName: string;          // 文档名称
  documentType: string;          // 文档类型
  year?: string;                 // 年份
  period?: string;               // 期间
  fileUrl?: string;              // 原始文件 URL（如有）
}
```

### 3.3 事件人性化处理

**核心原则**: 所有发送给前端的事件内容必须是用户友好的中文描述，而非技术性的原始日志。

#### 3.3.1 转换规则

后端需实现 `formatEventForUI()` 工具函数，将技术事件转换为用户友好的描述：

| 原始事件 | 人性化后 |
|----------|----------|
| `FunctionCall: query_vector_store({ query: "current assets", filter: { year: 2024 } })` | 正在搜索 "流动资产" 相关数据 (2024年)... |
| `FunctionCall: current_ratio({ year: "2024" })` | 正在计算流动比率... |
| `ToolResult: { current_ratio: 2.15, ... }` | 流动比率计算完成: 2.15 |
| `Error: API timeout` | 数据获取超时，正在重试... |

#### 3.3.2 设计原则

- **使用中文**: 面向财务人员，非技术人员
- **动作导向**: 使用 "正在..."、"已完成" 等表述
- **隐藏技术细节**: 不暴露函数名、参数结构
- **保留详情**: 原始技术信息保存在 `details` 字段，供高级用户查看

### 3.4 UI 展示需求

#### 3.4.1 折叠/展开行为

- **默认状态**: 过程日志折叠，仅显示触发按钮
- **触发方式**: 点击 "▶ 查看计算过程" 按钮展开
- **展开状态**: 显示完整的事件时间线
- **记忆状态**: 展开/折叠状态不需要跨消息保持

#### 3.4.2 视觉设计

#### 3.4.3 样式规范

| 元素 | 样式 |
|------|------|
| 容器 | 浅灰色背景 (`bg-neutral-50`)，圆角边框 |
| 事件图标 | 对应类型的 emoji |
| 时间线 | 左侧竖线连接各事件（可选） |
| 来源链接 | 蓝色文字，下划线，hover 变深 |
| 展开按钮 | 灰色文字，hover 显示手型光标 |

#### 3.4.4 错误展示策略

错误需要在两个位置展示，采用不同策略：

| 展示位置 | 内容 | 样式 |
|----------|------|------|
| **过程日志内** | 技术性错误详情（❌ 图标） | 红色文字，显示具体错误原因 |
| **主聊天气泡** | 用户友好的错误提示 | 正常样式，解释发生了什么并建议下一步 |

**示例**:

```
过程日志:
  ❌ 数据获取失败
     错误: 连接超时 (请求 2024年资产负债表)

主聊天气泡:
  "抱歉，获取财务数据时遇到问题。请检查是否已上传 2024 年资产负债表，
   或稍后重试。"
```

**设计原则**:
- 过程日志面向需要排查问题的用户，提供技术细节
- 主聊天面向普通用户，提供友好的解释和建议
- 错误不应阻断用户体验，而应引导用户解决问题

### 3.5 数据来源链接需求

#### 3.5.1 链接目标

当用户点击数据来源链接时：

| 场景 | 行为 |
|------|------|
| 文档有原始文件 URL | 打开原始文件（新标签页） |
| 文档无原始文件 | 跳转到文档详情页 `/documents?id={documentId}` |
| 引用合规法规 | 跳转到法规内容页面 |

#### 3.5.2 链接格式

- 显示文本: `{year}年{documentType}` 或文档名称
- 示例: "2024年资产负债表 [查看原文]"
- 链接样式: 蓝色，可点击

## 4. SSE 流式事件格式

### 4.1 现有 SSE 事件类型（v3.6）

```typescript
type SSEEventType = 'thinking' | 'tool_call' | 'content' | 'done' | 'error';
```

### 4.2 新增/增强的事件类型

在现有基础上增强，添加过程透明化所需的字段：

```typescript
// SSE 事件载荷
interface SSEProcessEvent {
  type: 'process';                // 新增事件类型
  data: ProcessEvent;             // 过程事件数据
}

// 增强现有事件，添加可选的过程信息
interface SSEToolCallEvent {
  type: 'tool_call';
  data: {
    tool: string;
    args: Record<string, unknown>;
    humanized: string;            // 新增：人性化描述
    sourceReference?: SourceReference;  // 新增：数据来源
  };
}
```

### 4.3 前端处理流程

```
SSE 流 → 解析事件 → 分类处理
                    ├─ content → 更新主聊天内容
                    ├─ process → 追加到过程日志
                    ├─ tool_call → 追加到过程日志 + 显示状态
                    └─ error → 过程日志（详情）+ 主聊天（友好提示）
```

## 5. 范围界定

### 5.1 本期范围内 (In Scope)

- [x] 定义过程事件类型和数据结构
- [x] 后端：在工作流中捕获并记录事件
- [x] 后端：通过 SSE 流式传输事件（复用 v3.6 基础设施）
- [x] 后端：事件人性化处理（`formatEventForUI()`）
- [x] 前端：实时更新的过程展示组件（可折叠）
- [x] 前端：数据来源链接（跳转到文档页或原始文件）
- [x] 前端：错误事件的友好展示
- [x] 支持所有财务计算工具的过程记录

### 5.2 本期范围外 (Out of Scope)

- [ ] 页码级数据溯源（Page 14 of 资产负债表）— 需评估文档分块系统支持情况
- [ ] 数据片段悬停预览（hover 显示原文上下文）— 作为 v4.x 增强
- [ ] 过程事件的数据库持久化存储 — 当前仅在响应中返回
- [ ] 过程日志的导出功能（PDF/Excel）
- [ ] 多轮对话的过程历史追溯

### 5.3 技术约束

| 约束 | 说明 |
|------|------|
| SSE 流式传输 | 复用 `/api/chat/stream` 端点，事件实时推送 |
| 内存存储 | 事件在工作流执行期间存储在内存中，不持久化 |
| 单次请求 | 每次请求独立，不跨请求保留事件历史 |
| 事件数量上限 | 单次请求最多 50 条事件，防止响应过大 |

## 6. 成功指标

| 指标 | 目标 |
|------|------|
| 功能完整性 | 所有财务计算工具都输出过程事件 |
| 实时性 | 事件在产生后 < 100ms 内推送到前端 |
| UI 可用性 | 过程日志实时更新，可正常展开/折叠 |
| 链接有效性 | 数据来源链接正确跳转 |
| 事件可读性 | 所有事件描述对非技术用户友好（中文） |

## 7. 风险与缓解

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| 事件过多导致响应过大 | 网络传输慢 | 限制事件数量上限（如 50 条） |
| 某些工具未正确记录事件 | 过程不完整 | 单元测试覆盖所有工具 |
| 数据来源引用缺失 | 链接不可用 | 优雅降级，显示"来源未知" |
