## 问题陈述

当前项目已具备核心功能与基础工程能力，但对“生产级展示”而言仍缺少几个关键证据：

1. **环境分离与发布验证**：缺少 staging 环境，发布前验证不完整
2. **质量与测试证据**：无集成/E2E 测试与覆盖率基线
3. **可观测性与运维**：缺少错误追踪、监控告警
4. **对外可信文档**：架构与安全说明分散，缺少权威文档

该版本目标是补齐这些“可信度缺口”，使项目具备可立即部署的生产级展示标准。

参考文档：`docs/plans/2026-01-17-production-readiness-gap-analysis-design.md`

## 范围

### 范围内

1. Staging 环境建立与自动化部署
2. 发布前验证（健康检查 + 冒烟测试）
3. 集成测试与最小 E2E 覆盖
4. 覆盖率基线与质量门禁
5. 监控/告警与错误追踪
6. 架构与安全文档化
7. 发布与回滚演练流程

### 范围外

- 数据备份/灾备（由公司数据库体系负责）
- 多区域/多集群部署
- 多租户与权限体系重构
- 大规模性能压测与容量规划

## 需求详情

### REQ-A1: 建立 Staging 环境

**当前状态**：仅有生产环境，缺乏发布前验证。

**目标状态**：
- 建立独立 staging 部署路径（目录/容器/环境变量分离）
- 使用隔离的数据源（独立 Supabase 项目或隔离 schema）
- staging 不可写入生产数据

**验收标准**：
- [ ] staging 环境可独立部署与访问
- [ ] staging 健康检查通过 (`/api/health`)
- [ ] staging 环境配置与访问方式在文档中记录

---

### REQ-A2: Staging 自动化部署

**目标状态**：
- GitHub Actions 在 `development` 分支推送时自动部署 staging
- 部署完成后执行健康检查

**验收标准**：
- [ ] 新增 `deploy-staging` 工作流
- [ ] 使用独立 secrets（STAGING_HOST/USER/KEY 等）
- [ ] 健康检查失败会阻断流程

---

### REQ-A3: 发布前冒烟验证

**目标状态**：
- 关键 API 冒烟测试脚本（health、sessions、auth、reports）
- 在 staging 部署完成后自动执行

**验收标准**：
- [ ] 冒烟脚本在 CI 中执行
- [ ] 失败会阻断发布
- [ ] 输出包含失败原因与接口路径

---

### REQ-B1: 集成测试覆盖关键 API

**目标状态**：
- 为核心 API 路由补齐集成测试（至少 3 条关键路径）

**验收标准**：
- [ ] 覆盖 `/api/chat` 或 `/api/chat/stream`
- [ ] 覆盖 `/api/reports/generate`
- [ ] 覆盖 `/api/documents/upload-temp`
- [ ] `npm run test -- --run` 可通过

---

### REQ-B2: 最小 E2E 覆盖

**目标状态**：
- 选型 E2E 工具（Playwright 或 Cypress）
- 仅实现 1-2 条“关键路径”用户流程

**验收标准**：
- [ ] 完成工具选型与基础配置
- [ ] 至少 1 条完整用户流程测试
- [ ] E2E 结果可在 CI 中运行（可标记为 non-blocking）

---

### REQ-B3: 覆盖率基线与门禁

**目标状态**：
- 建立覆盖率基线（例如 60%）
- CI 输出覆盖率报告

**验收标准**：
- [ ] `npm run test:coverage` 可生成报告
- [ ] 覆盖率阈值可配置（初期可较低）
- [ ] 覆盖率结果在 CI 可见

---

### REQ-C1: 错误追踪与告警

**目标状态**：
- 集成错误追踪（Sentry/GlitchTip 任选其一）
- 关键错误具备上下文（requestId、route）

**验收标准**：
- [ ] 运行时错误可在控制台/后台可视化
- [ ] 与现有日志 requestId 关联
- [ ] 禁止上报敏感信息

---

### REQ-C2: 基础监控与告警

**目标状态**：
- 对 `/api/health` 进行 uptime 监控
- 关键故障触发告警（邮件/IM）

**验收标准**：
- [ ] 有明确的健康检查监控工具或流程
- [ ] 告警配置记录在文档中

---

### REQ-D1: 架构总览文档

**目标状态**：
- 新增 `docs/ARCHITECTURE.md`
- 说明当前架构、数据流、核心依赖

**验收标准**：
- [ ] 架构图或结构化描述
- [ ] 关键模块职责与边界说明
- [ ] 部署拓扑简述

---

### REQ-D2: 安全文档

**目标状态**：
- 新增 `docs/SECURITY.md`
- 说明认证/授权边界、密钥策略、漏洞披露流程

**验收标准**：
- [ ] 明确安全边界与 threat model
- [ ] 说明密钥管理与环境变量规范
- [ ] 简要漏洞披露/联系流程

---

### REQ-D3: 事故响应与运维手册

**目标状态**：
- 新增 `docs/INCIDENT_RUNBOOK.md`
- 与 `docs/DEPLOYMENT_CHECKLIST.md` 对齐

**验收标准**：
- [ ] 明确事故分级与响应步骤
- [ ] 包含回滚/降级流程
- [ ] 记录常见故障排查路径

---

### REQ-E1: 发布与回滚演练

**目标状态**：
- 在 staging 进行一次完整发布演练
- 演练包含“发布 + 回滚 + 验证”

**验收标准**：
- [ ] 演练记录写入文档
- [ ] 回滚流程可复现
- [ ] 关键路径验证通过

---

### REQ-E2: 发布清单更新

**目标状态**：
- 更新 `docs/DEPLOYMENT_CHECKLIST.md`：新增 staging 流程与发布前门禁

**验收标准**：
- [ ] checklist 反映 staging 验证步骤
- [ ] checklist 反映冒烟测试与可观测性检查
