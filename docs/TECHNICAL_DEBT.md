### TD-001: 类型系统清理

**领域**: TypeScript 类型

**问题**:
V3.9 代码评审发现 14 个文件中有 **44 处 `as any`** 类型断言：
- Supabase 类型不匹配 (18 处)
- LangGraph 状态访问 (9 处)
- XLSX 解析 (7 处)
- 其他混合情况 (10 处)

**影响**:
- 编译时类型安全性降低
- 难以自信地重构
- 编译时无法捕获潜在的运行时错误

**建议解决方案**:
1. 重新生成 Supabase 类型并修复数据库相关断言
2. 改进 LangGraph 状态接口
3. 为不可避免的断言添加 `// REASON:` 注释

**工作量估计**: 中

**状态**: 进行中 - V3.11 需求已定义

**参考**: `docs/development-documentation/V3.11_PHASE1_REQ.md`

### TD-002: XLSX 类型限制

**领域**: 外部库

**问题**:
`xlsx` 库的 `sheet_to_json()` 返回 `unknown[]`，需要类型断言才能使用。这是库的固有限制，不是代码库问题。

**影响**:
- 轻微：边界明确，数据在解析时已验证
- 上传/提取路由中有 7 处

**建议解决方案**:
- 保持现状，添加 `// REASON:` 注释
- 未来：可以添加验证包装函数

**工作量估计**: 小（仅注释）

**状态**: 已接受 - 将在 V3.11 中添加注释

---

### TD-003: Agent 可观测性缺口

**领域**: 可观测性

**问题**:
LangGraph Agent 工作流没有 LangSmith 或同类追踪工具。复杂 Agent 行为的调试依赖控制台日志。

**影响**:
- 难以调试生产环境的 Agent 问题
- 无法看到每步的 Token 使用量
- 无 Agent 工作流的性能分析

**建议解决方案**:
集成 LangSmith 用于：
- 追踪可视化
- Token 使用量跟踪
- 性能指标

**工作量估计**: 中

**状态**: 延迟到 V5+ - 当前日志对单人开发足够

---

### TD-004: 手动部署

**领域**: 基础设施

**问题**:
通过 `docker compose up -d --build` 手动部署。没有 CI/CD 流水线，推送时没有自动化测试。

**影响**:
- 部署时有人为错误风险
- 没有自动回滚能力
- 没有部署前测试关卡

**建议解决方案**:
GitHub Actions 流水线：
- PR 时自动测试
- Docker 构建验证
- 自动部署到预发布环境

**工作量估计**: 中

**状态**: 延迟到 V5+ - 单人开发，手动部署足够
