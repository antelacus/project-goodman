## 已接受

> 接受的理由与重新评估的触发条件写在条目里；触发条件出现时重新裁定。

| ID     | 领域    | 描述与接受理由                                          | 触发条件 |

| TD-019 | 可靠性 | **Supabase 调用无重试，外部服务无熔断**。OpenAI 调用由 SDK 自带重试（默认 2 次，指数退避，覆盖 408/409/429/5xx 与连接错误）。接受理由：目前只有 Jason 一个用户，瞬时故障的影响面很小。 | 第一位真实外部用户 |
| TD-020 | 数据完整性 | **文档上传、财务数据写入无幂等键**，重试可能产生重复数据。接受理由：单用户，重复数据看得见、删得掉。 | 第一位真实外部用户 |
| TD-021 | 可观测性 | **LLM 用量无法按用户 / 功能归因，无响应缓存，总花费没有按 token 的上限**。生产与 staging 都经第三方 relay（预付费）；relay 不提供用量上限，总花费的兜底是预付余额（Jason 控制充值额度）。请求频率由用户用量限制约束（访客按会话每小时 20 条消息、1 份报告；访客可调用的 AI 接口——对话、快捷提取、报告生成、报告配置解析、文档上传（扫描件与图片走 OCR）——按 IP 每分钟 20 次；报告配置解析没有访客次数限制）。这些接口共用每个 IP 的同一份额度，同一出口 IP 后的多人会互相挤占；换一个会话或 IP 就不受限，所以它限不住总量。接受理由：单用户、访问量很低，余额即硬上限。按 token 设限留到后续版本。 | 第一位真实外部用户，或决定按 token 设限的版本 |

## 开发注意事项

> 环境配置和预期行为，非债务项。

- **Redis**: Docker 中通过 `goodman-redis` 主机名连接；启动时连接错误是预期的，应用会自动重试
- **环境变量**: `.env` 中包含 `$` 字符的变量需要转义
- **Docker**: 仅用于生产环境；本地开发使用 `npm run dev`
- **Supabase**: `.temp/` 目录已 gitignore，会自动重新生成
