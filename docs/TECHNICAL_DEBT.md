### TD-003: Agent 可观测性缺口

**领域**: 可观测性

**问题**:
LangGraph Agent 工作流没有 LangSmith 或同类追踪工具。复杂 Agent 行为的调试依赖控制台日志。

**影响**:

- 难以调试生产环境的 Agent 问题
- 无法看到每步的 Token 使用量
- 无 Agent 工作流的性能分析

**建议解决方案**:
集成 LangSmith 用于：

- 追踪可视化
- Token 使用量跟踪
- 性能指标

**工作量估计**: 中

**状态**: 延迟到 V5+ - 当前日志对单人开发足够

---

### TD-004: 手动部署

**领域**: 基础设施

**问题**:
通过 `docker compose up -d --build` 手动部署。没有 CI/CD 流水线，推送时没有自动化测试。

**影响**:

- 部署时有人为错误风险
- 没有自动回滚能力
- 没有部署前测试关卡

**建议解决方案**:
GitHub Actions 流水线：

- PR 时自动测试
- Docker 构建验证
- 自动部署到预发布环境

**工作量估计**: 中

**状态**: 延迟到 V5+ - 单人开发，手动部署足够

---

### TD-005: 性能基线缺失

**领域**: 性能

**问题**:
无打包大小分析、API 响应时间监控、Core Web Vitals 追踪。缺少性能优化的基线数据。

**影响**:

- 无法量化性能改进效果
- 性能退化难以发现
- 无法设定性能目标

**建议解决方案**:

- 打包分析器集成（@next/bundle-analyzer）
- API 响应时间日志
- Web Vitals 追踪

**工作量估计**: 小

**状态**: 纳入 V4.3 - 作为 Task J 实施（打包分析、API 响应时间、Web Vitals）

## 开发注意事项

> 环境配置和预期行为，非债务项。

- **Redis**: Docker 中通过 `goodman-redis` 主机名连接；启动时连接错误是预期的，应用会自动重试
- **环境变量**: `.env` 中包含 `$` 字符的变量需要转义
- **Docker**: 仅用于生产环境；本地开发使用 `npm run dev`
- **Supabase**: `.temp/` 目录已 gitignore，会自动重新生成
