## 1. 设计概述

### 1.1 设计目标

基于 Phase 1 需求声明，本设计文档定义：

1. **详细架构**：各组件如何协作
2. **配置模板**：可直接使用的配置文件
3. **安全措施**：具体的安全加固步骤
4. **实施任务**：按顺序执行的任务清单

### 1.2 设计原则

| 原则 | 说明 |
|------|------|
| **最小可行迁移** | 仅迁移必要组件，不引入新功能 |
| **零代码修改** | 应用代码保持不变 |
| **可回滚** | 保留 Vercel 部署，随时可回退 |
| **安全优先** | 从一开始就配置安全措施 |
| **容器化** | 使用 Docker 支持多项目部署 |

### 1.3 为什么选择 Docker

VPS 将托管多个不同技术栈的项目，Docker 提供：

| 优势 | 说明 |
|------|------|
| **项目隔离** | 每个项目独立运行，互不影响 |
| **版本自由** | 不同项目可使用不同 Node.js/Python 版本 |
| **简化清理** | 删除项目只需 `docker rm`，无残留 |
| **统一端口** | 所有项目容器内都用 3000，nginx 路由 |
| **环境一致** | 开发/生产环境配置相同 |

### 1.4 需求追溯

| 需求 ID | 需求描述 | 设计满足方式 |
|---------|----------|--------------|
| FR-1 | 域名访问 | Cloudflare DNS → nginx → Docker container |
| FR-2 | 功能一致 | 相同代码，相同环境变量 |
| FR-3 | 崩溃重启 | Docker `restart: unless-stopped` |
| FR-4 | 开机启动 | Docker daemon 自动启动容器 |
| FR-5 | 零停机部署 | `docker-compose up -d --build` (滚动更新) |
| FR-6 | WebSocket | nginx proxy_pass + upgrade headers |
| FR-7 | 无超时 | 移除 serverless 限制 |
| SR-1~7 | 安全需求 | 详见第 5 节 |

## 3. 组件详细设计

### 3.1 Cloudflare 配置

#### DNS 设置

| 类型 | 名称 | 内容 | 代理状态 | TTL |
|------|------|------|----------|-----|
| A | goodman | 104.168.38.213 | Proxied (橙云) | Auto |

#### SSL/TLS 设置

| 设置 | 值 | 说明 |
|------|-----|------|
| SSL Mode | Full (Strict) | 要求有效 Origin Certificate |
| Minimum TLS | TLS 1.2 | 安全最低版本 |
| Always Use HTTPS | On | 强制 HTTPS |
| Automatic HTTPS Rewrites | On | 混合内容修复 |

#### Origin Certificate

- **有效期**: 15 年 (Cloudflare 默认)
- **类型**: RSA (2048)
- **覆盖域名**: `*.antelacus.com, antelacus.com` (通配符，支持未来子域名)

### 3.2 nginx 设计

#### 职责

1. SSL 终止 (使用 Cloudflare Origin Certificate)
2. 按域名路由到不同 Docker 容器
3. IP 白名单 (仅允许 Cloudflare IP)
4. WebSocket 代理支持
5. 安全头注入

#### 关键配置点

| 配置项 | 值 | 原因 |
|--------|-----|------|
| `proxy_pass` | `http://goodman:3000` | Docker 容器名作为主机名 |
| `proxy_read_timeout` | 300s | 支持长时间 AI 请求 |
| `proxy_http_version` | 1.1 | WebSocket 要求 |
| `client_max_body_size` | 50M | 支持文件上传 |

#### nginx 与 Docker 网络

nginx 运行在主机上，需要连接到 Docker 网络才能通过容器名访问：

```bash
# 方案: 使用 host 端口映射
# docker-compose.yml 中将容器端口映射到 localhost
# nginx 通过 127.0.0.1:3000 访问
```

### 3.3 Docker 设计

#### 镜像策略

| 策略 | 说明 |
|------|------|
| **本地构建** | 在 VPS 上从 Dockerfile 构建 |
| **基础镜像** | `node:20-alpine` (轻量级) |
| **多阶段构建** | 减少最终镜像大小 |

#### 容器配置

| 配置项 | 值 | 说明 |
|--------|-----|------|
| `restart` | `unless-stopped` | 崩溃自动重启，手动停止除外 |
| `ports` | `127.0.0.1:3000:3000` | 仅本地访问 |
| `env_file` | `.env` | 环境变量文件 |

#### Docker Compose 功能

| 功能 | 命令 |
|------|------|
| 启动 | `docker-compose up -d` |
| 停止 | `docker-compose down` |
| 重建并更新 | `docker-compose up -d --build` |
| 查看日志 | `docker-compose logs -f` |
| 查看状态 | `docker-compose ps` |

### 3.4 Next.js Docker 配置

#### Dockerfile 策略

使用 Next.js 官方推荐的多阶段构建：

1. **deps stage**: 安装依赖
2. **builder stage**: 构建应用
3. **runner stage**: 运行生产版本 (最小镜像)

#### 环境变量处理

| 变量类型 | 处理方式 |
|----------|----------|
| `NEXT_PUBLIC_*` | 构建时注入 (需要在 build 阶段) |
| 服务端变量 | 运行时通过 `.env` 注入 |

## 4. 配置模板

### 4.1 Dockerfile

文件: `project-goodman/Dockerfile`

```dockerfile
# ============================================
# Stage 1: Dependencies
# ============================================
FROM node:20-alpine AS deps
RUN apk add --no-cache libc6-compat
WORKDIR /app

# Copy package files
COPY package.json package-lock.json* ./

# Install dependencies
RUN npm ci --only=production && npm cache clean --force

# ============================================
# Stage 2: Builder
# ============================================
FROM node:20-alpine AS builder
WORKDIR /app

# Copy dependencies from deps stage
COPY --from=deps /app/node_modules ./node_modules
COPY . .

# Build arguments for NEXT_PUBLIC_ variables
ARG NEXT_PUBLIC_SUPABASE_URL
ARG NEXT_PUBLIC_SUPABASE_ANON_KEY

# Set environment variables for build
ENV NEXT_PUBLIC_SUPABASE_URL=$NEXT_PUBLIC_SUPABASE_URL
ENV NEXT_PUBLIC_SUPABASE_ANON_KEY=$NEXT_PUBLIC_SUPABASE_ANON_KEY
ENV NEXT_TELEMETRY_DISABLED=1

# Build the application
RUN npm run build

# ============================================
# Stage 3: Runner
# ============================================
FROM node:20-alpine AS runner
WORKDIR /app

# Set production environment
ENV NODE_ENV=production
ENV NEXT_TELEMETRY_DISABLED=1

# Create non-root user for security
RUN addgroup --system --gid 1001 nodejs
RUN adduser --system --uid 1001 nextjs

# Copy built application
COPY --from=builder /app/public ./public
COPY --from=builder /app/.next/standalone ./
COPY --from=builder /app/.next/static ./.next/static

# Set correct permissions
USER nextjs

# Expose port
EXPOSE 3000

# Set hostname for container
ENV HOSTNAME="0.0.0.0"
ENV PORT=3000

# Start the application
CMD ["node", "server.js"]
```

### 4.6 nginx 配置

文件: `/etc/nginx/sites-available/goodman.antelacus.com`

```nginx
# Redirect HTTP to HTTPS
server {
    listen 80;
    listen [::]:80;
    server_name goodman.antelacus.com;

    # Only allow Cloudflare IPs
    include /etc/nginx/snippets/cloudflare-ips.conf;
    deny all;

    return 301 https://$server_name$request_uri;
}

# Main HTTPS server
server {
    listen 443 ssl http2;
    listen [::]:443 ssl http2;
    server_name goodman.antelacus.com;

    # Only allow Cloudflare IPs
    include /etc/nginx/snippets/cloudflare-ips.conf;
    deny all;

    # SSL Configuration (Cloudflare Origin Certificate)
    ssl_certificate /etc/nginx/ssl/cloudflare-origin.pem;
    ssl_certificate_key /etc/nginx/ssl/cloudflare-origin.key;
    ssl_protocols TLSv1.2 TLSv1.3;
    ssl_ciphers ECDHE-ECDSA-AES128-GCM-SHA256:ECDHE-RSA-AES128-GCM-SHA256:ECDHE-ECDSA-AES256-GCM-SHA384:ECDHE-RSA-AES256-GCM-SHA384;
    ssl_prefer_server_ciphers off;

    # Security Headers
    add_header X-Frame-Options "SAMEORIGIN" always;
    add_header X-Content-Type-Options "nosniff" always;
    add_header X-XSS-Protection "1; mode=block" always;
    add_header Referrer-Policy "strict-origin-when-cross-origin" always;

    # Proxy to Docker container
    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_http_version 1.1;

        # Headers for Next.js
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;

        # WebSocket support
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";

        # Timeouts for long-running requests (AI operations)
        proxy_connect_timeout 60s;
        proxy_send_timeout 300s;
        proxy_read_timeout 300s;

        # Buffering settings
        proxy_buffering off;
        proxy_request_buffering off;
    }

    # File upload size limit
    client_max_body_size 50M;

    # Gzip compression
    gzip on;
    gzip_vary on;
    gzip_proxied any;
    gzip_comp_level 6;
    gzip_types text/plain text/css text/xml application/json application/javascript application/rss+xml application/atom+xml image/svg+xml;
}

# Block direct IP access
server {
    listen 80 default_server;
    listen [::]:80 default_server;
    listen 443 ssl default_server;
    listen [::]:443 ssl default_server;

    ssl_certificate /etc/nginx/ssl/cloudflare-origin.pem;
    ssl_certificate_key /etc/nginx/ssl/cloudflare-origin.key;

    server_name _;
    return 444;
}
```

## 5. 安全设计

### 5.1 安全层次

```
Layer 1: Cloudflare
├── DDoS Protection (自动)
├── WAF Basic Rules (自动)
├── SSL/TLS Encryption (配置)
└── Bot Protection (自动)

Layer 2: UFW Firewall
├── 仅开放 22, 80, 443
└── 默认拒绝所有入站

Layer 3: nginx
├── Cloudflare IP 白名单
├── 阻止直接 IP 访问
├── 安全响应头
└── 请求大小限制

Layer 4: Docker
├── 容器隔离
├── 非 root 用户运行
├── 仅暴露必要端口到 localhost
└── 只读文件系统 (可选)

Layer 5: Application
├── 环境变量安全存储
├── 现有 RLS 策略
└── 现有输入验证
```

### 5.2 安全检查表

## 9. 后续维护指南

### 9.1 资源监控

部署第二个项目前，先监控 Goodman 的实际资源使用：

```bash
# 查看容器资源使用
docker stats goodman

# 持续监控 (每 5 秒刷新)
watch -n 5 docker stats goodman --no-stream
```

当部署第二个项目时：
1. 取消 `docker-compose.yml` 中资源限制的注释
2. 根据监控数据调整 `memory` 限制值
3. 为新项目设置适当的限制

### 9.2 添加新项目检查表

添加新项目 (如 `projectb.antelacus.com`) 时：

- [ ] 创建项目目录: `$DEPLOY_HOME/projectb/`
- [ ] 生成新的 SSH Deploy Key (如果是私有仓库)
- [ ] 创建 `docker-compose.yml` (使用不同端口, 如 3001)
- [ ] 创建 nginx 配置: `/etc/nginx/sites-available/projectb.antelacus.com`
- [ ] 在 Cloudflare 添加 DNS 记录 (A 记录, Proxied)
- [ ] 启用 Goodman 的资源限制
- [ ] 为新项目设置资源限制
- [ ] 添加到 UptimeRobot 监控

### 9.3 共享服务激活

当需要 Redis 或其他共享服务时：

```bash
# 1. 创建共享服务目录
mkdir -p $DEPLOY_HOME/shared
cd $DEPLOY_HOME/shared

# 2. 创建 docker-compose.yml (示例)
cat > docker-compose.yml << 'EOF'
version: '3.8'
services:
  redis:
    image: redis:alpine
    container_name: shared-redis
    restart: unless-stopped
    networks:
      - shared-network
    volumes:
      - redis-data:/data

networks:
  shared-network:
    external: true

volumes:
  redis-data:
EOF

# 3. 启动共享服务
docker-compose up -d

# 4. 更新需要 Redis 的项目的 docker-compose.yml
# 添加 networks: shared-network: external: true
```
