## 1. 概述

### 1.1 背景

V3.1 完成了 LangGraph 预备重构，将三个核心工作流（Financial Analysis、Guidance Chat、Landing Chat）从单体 API 路由提取为独立的步骤函数和手动编排器。V3.4 的目标是将这些工作流迁移到 LangGraph StateGraph 框架，实现声明式图编排。

### 1.2 目标

将现有手动编排的工作流迁移到 LangGraph StateGraph，获得以下收益：

1. **声明式流程定义** - 用图结构替代 if/else 分支逻辑
2. **条件边** - 显式定义错误处理和数据不足场景的流转
3. **可扩展性** - 为未来功能（流式响应、对话记忆）奠定基础
4. **可维护性** - 利用行业标准框架，便于调试和文档查阅

### 1.3 非目标（明确排除）

以下功能 **不在 V3.4 范围内**：

| 功能 | 延迟至 | 原因 |
|------|--------|------|
| 流式响应 / WebSocket | V3.6+ | 用户体验优化，非核心功能 |
| 对话记忆持久化 | V3.6+ | 需要额外存储设计 |
| LangSmith 可观测性 | 未定 | 开发调试工具，非生产必需 |

## 3. 目标架构

### 3.1 LangGraph StateGraph 模式

```typescript
import { StateGraph, START, END, Annotation } from "@langchain/langgraph";

// 1. 定义状态注解（基于现有 FinancialAnalysisState）
const StateAnnotation = Annotation.Root({
  input: Annotation<InputType>,
  routing: Annotation<RoutingType>,
  dataQuery: Annotation<DataQueryType>,
  calculation: Annotation<CalculationType>,
  confidence: Annotation<ConfidenceType>,
  output: Annotation<OutputType>,
});

// 2. 节点函数（适配现有步骤函数）
const routeNode = async (state: typeof StateAnnotation.State) => {
  const result = await steps.routeToFunction(state);
  return { routing: result.routing };
};

// 3. 条件边函数
const shouldQueryData = (state: typeof StateAnnotation.State) => {
  if (!state.routing?.selectedFunction) return "generateResponse";
  return "queryData";
};

// 4. 构建图
const workflow = new StateGraph(StateAnnotation)
  .addNode("routeToFunction", routeNode)
  .addNode("queryData", queryNode)
  .addNode("executeCalculation", calcNode)
  .addNode("evaluateConfidence", confidenceNode)
  .addNode("generateResponse", responseNode)
  .addEdge(START, "routeToFunction")
  .addConditionalEdges("routeToFunction", shouldQueryData)
  .addConditionalEdges("queryData", hasRequiredData)
  .addEdge("executeCalculation", "evaluateConfidence")
  .addEdge("evaluateConfidence", "generateResponse")
  .addEdge("generateResponse", END);

// 5. 编译并导出
export const financialAnalysisGraph = workflow.compile();
```

## 4. 工作流迁移规格

### 4.1 Landing Chat Workflow

**当前步骤**:
1. `generateReply` - 生成对话回复
2. `analyzeRouting` - 分析意图并路由
3. `generateSuggestions` - 生成推荐问题
4. `generateResponse` - 构建最终响应

**目标图结构**:
```
START → generateReply → analyzeRouting → generateSuggestions → generateResponse → END
```

**条件边**: 无（线性流程）

**复杂度**: 低（最简单，适合作为 PoC）

### 4.2 Financial Analysis Workflow

**当前步骤**:
1. `selectDocuments` - 智能文档选择 (V3.3 新增)
2. `routeToFunction` - 路由到计算函数
3. `queryData` - 查询财务数据
4. `executeCalculation` - 执行计算
5. `evaluateConfidence` - 评估置信度
6. `generateResponse` - 生成自然语言响应

**目标图结构**:
```
                                    ┌─────────────────────────────────────────────────┐
                                    │                                                 │
START → selectDocuments → routeToFunction                                             │
                                │                                                     │
                    ┌───────────┴───────────┐                                         │
                    │ (成功匹配函数)         │ (无匹配函数)                             │
                    ↓                       ↓                                         │
               queryData              generateResponse ─────────────────────────→ END │
                    │                                                                 │
        ┌───────────┴───────────┐                                                     │
        │ (数据充足)             │ (数据不足)                                          │
        ↓                       ↓                                                     │
executeCalculation         generateResponse ─────────────────────────────────────→ END
        │
        ↓
evaluateConfidence
        │
        ↓
generateResponse ─────────────────────────────────────────────────────────────────→ END
```

**条件边**:
1. `routeToFunction` → `queryData` (成功) | `generateResponse` (无匹配函数)
2. `queryData` → `executeCalculation` (数据充足) | `generateResponse` (数据不足)

**复杂度**: 中等

### 4.3 Guidance Chat Workflow

**当前步骤**:
1. `selectDocuments` - 智能文档选择 (V3.3 新增)
2. `performHybridSearch` - 混合搜索
3. `generateGuidance` - 生成合规指导（含工具调用）
4. `findRelatedArticles` - 查找相关条款
5. `evaluateConfidence` - 评估置信度
6. `generateResponse` - 构建最终响应

**目标图结构**:
```
START → selectDocuments → performHybridSearch ─┬─→ generateGuidance → findRelatedArticles
                                               │
                                               ↓ (无搜索结果)
                                          generateResponse → END

findRelatedArticles → evaluateConfidence → generateResponse → END
```

**条件边**:
1. `performHybridSearch` → `generateGuidance` | `generateResponse` (基于搜索结果)

**复杂度**: 中等（含工具调用循环）

### 5.3 Reducer 策略（类型安全关键）

> **背景问题**: LangGraph 默认行为是**覆盖**整个字段，而非合并。如果节点只返回部分字段，其他字段可能丢失。对于财务数据，字段丢失意味着计算上下文丢失。

#### 5.3.1 LangGraph 默认行为

```typescript
// 危险示例：无 reducer
const State = Annotation.Root({
  dataQuery: Annotation<DataQueryType>,  // 无 reducer = 覆盖
});

// 节点返回
return { dataQuery: { requiredMetrics: [...] } };
// 结果：dataQuery.availableMetrics, dataQuery.missingMetrics 全部丢失！
```

#### 5.3.2 解决方案：显式 Reducer

**策略**: 为每个复杂字段定义 reducer，确保合并而非覆盖。

```typescript
const FinancialAnalysisAnnotation = Annotation.Root({
  // 简单字段：保留最新值（后者优先，null 保留前者）
  input: Annotation<InputType>({
    reducer: (prev, next) => next ?? prev,
    default: () => ({}),
  }),

  // 复杂对象：深度合并
  routing: Annotation<RoutingType>({
    reducer: (prev, next) => ({ ...prev, ...next }),
    default: () => ({}),
  }),

  dataQuery: Annotation<DataQueryType>({
    reducer: (prev, next) => ({ ...prev, ...next }),
    default: () => ({
      requiredMetrics: [],
      availableMetrics: [],
      missingMetrics: [],
      dataMap: {},
      sourceDocuments: [],
    }),
  }),

  calculation: Annotation<CalculationType>({
    reducer: (prev, next) => ({ ...prev, ...next }),
    default: () => ({}),
  }),

  confidence: Annotation<ConfidenceType>({
    reducer: (prev, next) => ({ ...prev, ...next }),
    default: () => ({ score: 0, factors: [], threshold: 0.6, passed: false }),
  }),

  // 数组字段：追加而非覆盖
  meta: Annotation<WorkflowMeta>({
    reducer: (prev, next) => ({
      ...prev,
      ...next,
      errors: [...(prev?.errors || []), ...(next?.errors || [])],
    }),
    default: () => ({ startTime: Date.now(), currentStep: '', errors: [] }),
  }),
});
```

#### 5.3.3 验证清单

| 字段 | Reducer 策略 | 风险等级 |
|------|-------------|---------|
| `input` | 保留最新 | 低 |
| `routing` | 对象合并 | 中 |
| `dataQuery` | 对象合并 | **高**（财务数据） |
| `calculation` | 对象合并 | **高**（计算结果） |
| `confidence` | 对象合并 | 中 |
| `output` | 保留最新 | 低 |
| `meta.errors` | 数组追加 | 中 |

### 5.5 错误处理策略（Result Pattern）

> **设计决策**: 采用 **Result Pattern**（状态内错误字段）而非节点内抛出异常。

#### 5.5.1 为什么选择 Result Pattern

| 方案 | 优点 | 缺点 |
|------|------|------|
| **异常抛出** | LangGraph 原生支持，代码简洁 | 错误信息难以传递到 `generateResponse`；难以生成人类可读的错误解释 |
| **Result Pattern** | 错误上下文完整保留，`generateResponse` 可生成详细解释 | 需要在状态中维护错误字段 |

**选择 Result Pattern 的原因**:
- 财务系统需要向用户解释"为什么失败"（如："未找到2024年的资产负债表"）
- 区分"正常逻辑分支"和"异常处理"更清晰
- 错误上下文可用于审计追踪

#### 5.5.2 状态错误字段设计

```typescript
// 在每个子状态中添加可选错误字段
interface DataQueryState {
  requiredMetrics: string[];
  availableMetrics: string[];
  missingMetrics: string[];
  dataMap: Record<string, number>;
  sourceDocuments: SourceDocument[];
  // Result Pattern: 错误字段
  error?: {
    code: string;           // 'INSUFFICIENT_DATA' | 'QUERY_FAILED' | ...
    message: string;        // 人类可读消息
    details?: {
      missingItems?: string[];  // 具体缺失项
      suggestion?: string;      // 建议操作
    };
  };
}
```

#### 5.5.3 条件边：区分正常分支与错误处理

```typescript
// 条件边路由函数
const afterQueryData = (state: typeof StateAnnotation.State): string => {
  // 错误处理路径
  if (state.dataQuery.error) {
    return "generateResponse";  // → 生成错误解释
  }

  // 正常逻辑分支：数据不足（非错误，是业务逻辑）
  if (state.dataQuery.missingMetrics.length > 0) {
    return "generateResponse";  // → 生成"需要更多数据"的响应
  }

  // 正常路径
  return "executeCalculation";
};
```

#### 5.5.4 generateResponse 错误解释

```typescript
// generateResponse 节点需要处理多种场景
const generateResponseNode = async (state: State) => {
  // 场景 1: 有错误
  if (state.dataQuery?.error) {
    return {
      output: {
        type: 'error',
        answer: generateHumanReadableError(state.dataQuery.error),
        // 示例: "抱歉，查询2024年财务数据时发生错误：未找到资产负债表文件。"
      }
    };
  }

  // 场景 2: 数据不足（正常业务逻辑）
  if (state.dataQuery?.missingMetrics?.length > 0) {
    return {
      output: {
        type: 'insufficient_data',
        answer: `无法计算，缺少以下指标：${state.dataQuery.missingMetrics.join('、')}`,
        missingMetrics: state.dataQuery.missingMetrics,
      }
    };
  }

  // 场景 3: 正常计算结果
  // ... 调用 LLM 生成解释
};

// 辅助函数：生成人类可读的错误消息
function generateHumanReadableError(error: DataQueryError): string {
  const templates: Record<string, (e: DataQueryError) => string> = {
    'INSUFFICIENT_DATA': (e) =>
      `未找到${e.details?.missingItems?.join('、') || '必需数据'}，请确认已上传相关文档。`,
    'DOCUMENT_NOT_FOUND': (e) =>
      `未找到${e.details?.year || ''}年的${e.details?.docType || '财务报表'}。`,
    'QUERY_FAILED': (e) =>
      `数据查询失败：${e.message}。请稍后重试。`,
  };
  return templates[error.code]?.(error) || error.message;
}
```

#### 5.6.2 图可视化脚本

**交付物**: 创建脚本导出每个工作流的图结构为 Mermaid 图和 PNG 图片。

**脚本位置**: `scripts/export-graph-diagrams.ts`

```typescript
// scripts/export-graph-diagrams.ts
import * as fs from 'fs';
import * as path from 'path';

// 导入编译后的图
import { financialAnalysisGraph } from '../src/lib/workflows/financial-analysis/graph';
import { guidanceChatGraph } from '../src/lib/workflows/guidance-chat/graph';
import { landingChatGraph } from '../src/lib/workflows/landing-chat/graph';

async function exportGraphDiagrams() {
  const graphs = [
    { name: 'financial-analysis', graph: financialAnalysisGraph },
    { name: 'guidance-chat', graph: guidanceChatGraph },
    { name: 'landing-chat', graph: landingChatGraph },
  ];

  const outputDir = path.join(__dirname, '../docs/graphs');
  fs.mkdirSync(outputDir, { recursive: true });

  for (const { name, graph } of graphs) {
    const drawable = graph.getGraph();

    // 导出 Mermaid 文本（可在 Markdown 中直接使用）
    // Note: 需要确认 LangGraph 是否有 toMermaid() 方法
    // 如果没有，可以使用 drawMermaidPng()

    // 导出 PNG 图片
    try {
      const image = await drawable.drawMermaidPng();
      const arrayBuffer = await image.arrayBuffer();
      const buffer = Buffer.from(arrayBuffer);

      const pngPath = path.join(outputDir, `${name}-graph.png`);
      fs.writeFileSync(pngPath, buffer);
      console.log(`Exported: ${pngPath}`);
    } catch (error) {
      console.error(`Failed to export ${name}:`, error);
    }
  }
}

exportGraphDiagrams().catch(console.error);
```
