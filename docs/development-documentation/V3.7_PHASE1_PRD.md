## 1. 背景与目标

### 1.1 项目背景

V3.6 完成后，Project Goodman 已拥有统一的对话入口 `/chat`，整合了财务分析、合规指导、信息提取等所有功能模块。然而当前 UI 仅为功能性实现，存在以下问题：

- 顶部导航栏占用垂直空间，不适合对话型应用
- 页面间导航逻辑不够清晰
- 视觉风格缺乏专业感和一致性
- 移动端体验欠佳

### 1.2 项目阶段

Project Goodman 正在从**演示项目**演进为**生产可用工具**，服务于双重目标：

| 目标 | 描述 |
|------|------|
| **能力展示** | 向潜在雇主展示开发者在财务 AI Agent 领域的专业能力 |
| **实际价值** | 证明项目可集成到企业内部工作流，为财务人员提供实际帮助 |

### 1.3 升级目标

| 目标 | 描述 |
|------|------|
| **美观 (Beautiful)** | 专业的企业级视觉设计，传递安全感和可信度 |
| **实用 (Useful)** | 清晰的导航结构，高效的操作流程 |
| **健壮 (Robust)** | 完善的响应式设计，适配桌面和移动端 |

## 2. 目标用户

### 2.1 双重受众

| 受众 | 目的 | 关键体验 |
|------|------|----------|
| **潜在雇主** | 评估开发者能力 | Landing 页面吸引力、专业印象、技术展示 |
| **企业员工** | 日常工作工具 | 快速上手、高效工作流、可靠功能 |

### 2.2 用户画像

**主要用户**: 会计部门财务人员

- 日常进行财务分析、合规检查、数据提取
- 偏好传统、稳重的界面风格（传递安全感）
- 需要快速上手，无需复杂培训

**次要访客**: 招聘方、技术评审者

- 通过 Landing 页面了解项目
- 可能使用手机浏览
- 关注技术能力展示和项目完整度

## 4. 页面结构

### 4.1 页面路由

| 路由 | 页面名称 | 描述 |
|------|----------|------|
| `/` | Landing | 项目展示页，吸引潜在雇主 |
| `/chat` | 工作台 | 主工作区，统一对话界面 |
| `/documents` | 文档管理 | 管理已上传文档（未来演进为项目管理） |
| `/help` | 帮助 | README 内容展示 |
| `/about` | 关于 | 项目和开发者介绍 |

### 4.2 导航逻辑

```
Landing (/)
    │
    └── "开始使用" ──→ 工作台 (/chat)
                           │
                    ┌──────┴──────┐
                    ↓             ↓
              侧边栏导航      主内容区
```

## 5. 侧边栏设计

### 5.1 结构 (从上到下)

```
┌─────────────────────────────┐
│  Logo                       │  → 点击跳转 Landing 页
├─────────────────────────────┤
│  ★ 新建对话                  │  → 最高优先级，主入口 (重置当前会话)
├─────────────────────────────┤
│  快捷工具                    │
│    └─ 财务信息提取            │  → 快速访问提取工具 (打开上传模态框)
├─────────────────────────────┤
│  ┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄  │  (未来: 所有对话 - V3.10)
├─────────────────────────────┤
│  文档管理                    │  → 跳转 /documents
├─────────────────────────────┤
│  ┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄  │  (未来: 最近会话 - V3.10)
├─────────────────────────────┤
│  帮助                       │  → 跳转 /help
│  关于                       │  → 跳转 /about
├─────────────────────────────┤
│  [联系我]                    │  → 联系方式按钮
│  ┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄  │  (未来: 登录/登出 - V3.10)
└─────────────────────────────┘
```

### 5.2 折叠/展开行为

参考 Claude 网页版设计：

| 状态 | 显示内容 | 宽度 |
|------|----------|------|
| **折叠** | 仅图标 | ~60px |
| **展开** | 图标 + 文字 | ~240px |

**交互方式**:

- 点击折叠/展开按钮切换状态
- 用户偏好应被记住（localStorage）

### 5.3 移动端行为

| 行为 | 描述 |
|------|------|
| **默认状态** | 侧边栏隐藏 |
| **Header**   | 新增移动端顶部 Header，包含 Logo 和 汉堡菜单 |
| **触发方式** | 点击 Header 上的汉堡菜单图标 |
| **展开方式** | 从左侧滑出，覆盖内容区 (Overlay) |
| **关闭方式** | 点击遮罩层或关闭按钮 |

## 6. 视觉设计规范

### 6.1 设计风格

**风格**: Professional Corporate（专业企业风格）

| 特征 | 说明 |
|------|------|
| **信息密度** | 适中，预留未来功能扩展空间 |
| **视觉感受** | 传统、稳重、专业 |
| **目标效果** | 为财务人员传递安全感和可信度 |

### 6.2 配色方案

保持当前配色（黑色，灰色，黄色）：

| 用途 | 颜色 | 说明 |
|------|------|------|
| **主色** | 黑色 | 专业、可信 |
| **背景** | 浅灰/白色 | 清晰、易读 |
| **强调** | 黄色 | 按钮、链接、选中状态 |

### 6.3 排版

| 元素 | 规范 |
|------|------|
| **字体** | 系统字体栈（无需自定义字体） |
| **间距** | 统一的间距系统（Tailwind 默认） |
| **图标** | 线性图标风格，保持一致性 |

## 7. 成功标准

### 7.1 功能验收

- [ ] 侧边栏正常显示所有导航项
- [ ] 侧边栏折叠/展开功能正常
- [ ] 所有页面路由正常访问
- [ ] 帮助页面正确显示 README 内容
- [ ] Landing 页面视觉升级完成
- [ ] 快捷工具（信息提取）点击弹出模态框

### 7.2 响应式验收

- [ ] 桌面端（>1024px）：侧边栏常驻，可折叠
- [ ] 平板端（768-1024px）：侧边栏默认折叠
- [ ] 移动端（<768px）：侧边栏隐藏，汉堡菜单触发

### 7.3 用户体验验收

- [ ] 首次访问用户能在 10 秒内理解如何开始使用
- [ ] 导航结构清晰，无需说明即可找到所需功能
- [ ] 视觉风格统一，无明显不协调元素

## 8. 技术考量

### 8.1 实现建议

| 方面 | 建议 |
|------|------|
| **侧边栏组件** | 创建独立的 `Sidebar` 组件 |
| **状态管理** | 侧边栏状态可用 Zustand 或 localStorage |
| **响应式** | 使用 Tailwind 断点系统 |
| **图标库** | **Lucide React** (与 shadcn/ui 兼容，现代风格) |

### 8.2 兼容性

- 支持主流现代浏览器（Chrome, Firefox, Safari, Edge）
- 移动端支持 iOS Safari 和 Android Chrome
