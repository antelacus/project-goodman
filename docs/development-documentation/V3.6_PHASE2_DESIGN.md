## 1. 设计概述

### 1.1 设计目标

基于 V3.6 PRD 的需求，本设计文档定义以下技术目标：

| 目标 | 描述 |
|------|------|
| **消除代码重复** | 提取 ~400 行重复的节点代码到共享模块 |
| **统一工具架构** | 所有工具注册到单一 toolRegistry |
| **统一 Agent Graph** | 单一 StateGraph 替代 3 个独立 Graph |
| **实时反馈** | WebSocket 推送 Agent 执行状态 |
| **简化入口** | 单一 `/chat` 页面替代 3 个模块页面 |

### 1.2 设计原则

1. **复用优先**: 最大化复用现有 LangGraph 模式，而非重写
2. **增量迁移**: 保留旧模块直到新系统验证完成
3. **向后兼容**: API 端点可并行运行（新旧共存）
4. **关注点分离**: 核心节点逻辑 vs 领域特定逻辑清晰分离

### 1.3 现有代码分析

基于代码库探索，识别以下关键点：

**高度重复代码** (需要提取):

- `loadMemoryNode` - 3 个工作流中几乎相同
- `agentNode` (Agent 循环) - financial-analysis 与 guidance-chat 重复 ~200 行
- `toolNode` - 工具执行逻辑重复
- `saveMemoryNode` - 消息保存逻辑相同
- OpenAI 工具格式转换 - 两处重复实现

**可直接复用** (无需修改):

- `ToolRegistry` - 已支持多类别工具
- `ConversationMemory` - 工作流无关的会话管理
- `graph-utils.ts` - 日志和错误处理工具
- 现有 22 个财务计算工具

## 3. V3.6a: 统一 Agent 设计

### 3.1 核心节点提取

从现有 `financial-analysis/nodes.ts` 和 `guidance-chat/nodes.ts` 提取共享逻辑。

#### 3.1.1 LoadMemoryNode

**位置**: `workflows/core/nodes/load-memory.ts`

**设计思路**: 参数化工作流类型，其他逻辑完全复用。

```
输入: { sessionId?: string, workflowType: string }
输出: { agent: { sessionId, messages[] } }

逻辑:
1. 调用 conversationMemory.getOrCreateSession(sessionId, workflowType)
2. 转换已存储消息为 OpenAI 消息格式
3. 返回更新后的 agent 状态
```

#### 3.1.2 AgentLoopNode

**位置**: `workflows/core/nodes/agent-loop.ts`

**设计思路**: 参数化系统提示词和工具集，Agent 循环逻辑完全复用。

```
输入: { agent: AgentState, systemPrompt: string, tools: Tool[] }
输出: { agent: AgentState, toolResults?: ToolResult[] }

逻辑:
1. 构建消息数组 [systemPrompt, ...agent.messages, userMessage]
2. 调用 OpenAI chat.completions.create({ tools, tool_choice: "auto" })
3. 解析响应:
   - 如果有 tool_calls → 设置 pendingToolCalls
   - 如果无 tool_calls → 设置 isComplete
4. 增加迭代计数
5. 返回更新后的 agent 状态
```

#### 3.1.3 ToolExecutorNode

**位置**: `workflows/core/nodes/tool-executor.ts`

**设计思路**: 统一工具执行，通过 ToolRegistry 路由。

```
输入: { agent: AgentState (with pendingToolCalls) }
输出: { agent: AgentState, toolResults: ToolResult[] }

逻辑:
1. 遍历 pendingToolCalls
2. 对每个 tool_call:
   a. toolRegistry.get(tool_call.function.name)
   b. 解析参数 JSON.parse(tool_call.function.arguments)
   c. tool.execute(parsedArgs)
   d. 构建 tool message 添加到 messages
3. 清空 pendingToolCalls
4. 返回更新后状态
```

#### 3.1.4 SaveMemoryNode

**位置**: `workflows/core/nodes/save-memory.ts`

**设计思路**: 完全复用，无需参数化。

```
输入: { agent: AgentState }
输出: {} (无状态变更，仅副作用)

逻辑:
1. 过滤出未保存的消息 (无 id 字段)
2. 调用 conversationMemory.saveMessages(sessionId, newMessages)
```

### 3.2 统一 Agent 状态设计

**位置**: `workflows/unified/state.ts`


**条件边逻辑** (afterAgentNode):

```typescript
function afterAgentNode(state: UnifiedAgentState): string {
  // 1. 达到最大迭代次数
  if (state.agent.currentIteration >= state.agent.maxIterations) {
    return 'generateResponse';
  }

  // 2. Agent 标记完成
  if (state.agent.isComplete) {
    return 'generateResponse';
  }

  // 3. 有待执行的工具调用
  if (state.agent.pendingToolCalls?.length > 0) {
    return 'toolNode';
  }

  // 4. 默认完成
  return 'generateResponse';
}
```

## 4. V3.6b: WebSocket 流式响应设计

### 4.1 技术选型

| 方案 | 优点 | 缺点 | 选择 |
|------|------|------|------|
| **Next.js 自定义服务器** | 与应用集成紧密 | 需要修改启动方式 | ❌ |
| **独立 WS 端点 (ws 库)** | 简单直接 | 需要额外进程管理 | ❌ |
| **Socket.io** | 自动重连、房间管理 | 额外依赖 | ❌ |
| **API Route + SSE** | 无需额外服务 | 兼容性限制 | ✅ 首选 |

**决策**: 使用 **Server-Sent Events (SSE)** 作为首选方案。

**原因**:

1. Next.js API Routes 原生支持 SSE
2. 单向通信（服务器 → 客户端）满足需求
3. 无需修改 nginx 配置
4. 自动重连支持
5. 如 SSE 不足，可后续升级到 WebSocket

### 4.2 SSE 实现设计

#### 4.2.1 流式端点

**位置**: `app/api/chat/stream/route.ts`

```typescript
// SSE 端点
export async function POST(req: Request) {
  const body = await req.json();

  // 创建 ReadableStream
  const stream = new ReadableStream({
    async start(controller) {
      // 发送事件的辅助函数
      const sendEvent = (type: string, data: object) => {
        controller.enqueue(
          `event: ${type}\ndata: ${JSON.stringify(data)}\n\n`
        );
      };

      // 运行 Graph 并监听状态更新
      const graph = createUnifiedAgentGraph();

      for await (const event of graph.streamEvents(initialState)) {
        if (event.event === 'on_chain_start') {
          sendEvent('thinking', { node: event.name });
        }
        if (event.event === 'on_tool_start') {
          sendEvent('tool_call', { tool: event.name });
        }
        if (event.event === 'on_tool_end') {
          sendEvent('tool_result', { result: event.data });
        }
      }

      // 发送最终结果
      sendEvent('complete', { output: finalState.output });
      controller.close();
    }
  });

  return new Response(stream, {
    headers: {
      'Content-Type': 'text/event-stream',
      'Cache-Control': 'no-cache',
      'Connection': 'keep-alive',
    },
  });
}
```

#### 4.2.2 事件协议

```typescript
// 状态事件类型
type StreamEventType =
  | 'thinking'      // Agent 正在思考
  | 'tool_call'     // 开始调用工具
  | 'tool_result'   // 工具返回结果
  | 'partial'       // 部分响应
  | 'complete'      // 完成
  | 'error';        // 错误

// 事件数据结构
interface StreamEvent {
  type: StreamEventType;
  timestamp: number;
  data: {
    node?: string;           // 当前节点名称
    tool?: string;           // 工具名称
    toolInput?: object;      // 工具输入
    toolOutput?: object;     // 工具输出
    partial?: string;        // 部分文本
    output?: UnifiedOutput;  // 最终输出
    error?: string;          // 错误信息
  };
}
```

### 5.4 文件上传流程

```
1. 用户点击 📎 或拖拽文件
2. 前端调用 /api/documents/upload-temp 上传
3. 获取临时 fileUrl
4. fileUrl 随消息发送到 /api/chat
5. Agent 调用 extract_document_info 工具
6. 返回提取结果
```

## 7. API 设计

### 7.1 新增端点

#### POST /api/chat

**描述**: 统一对话端点（同步响应）

**请求**:

```typescript
interface ChatRequest {
  question: string;
  sessionId?: string;
  files?: Array<{
    url: string;
    name: string;
    type: string;
  }>;
  documentIds?: number[];  // 可选手动指定
}
```

**响应**:

```typescript
interface ChatResponse {
  sessionId: string;
  answer: string;
  type: 'success' | 'error' | 'need_clarification';
  calculations?: Calculation[];
  citations?: Citation[];
  extractedData?: ExtractedData;
  sourceDocuments?: SourceDoc[];
  confidence?: number;
}
```

#### POST /api/chat/stream

**描述**: 流式对话端点（SSE）

**请求**: 同 `/api/chat`

**响应**: Server-Sent Events 流

### 7.2 废弃端点 (V3.6c 后)

以下端点在新 UI 上线后可废弃：

| 端点 | 替代方案 |
|------|----------|
| POST /api/financial-analysis | /api/chat |
| POST /api/guidance-chat | /api/chat |
| POST /api/data-extract | /api/chat (extract_document_info 工具) |

