## Phase A: 数据库迁移

### A1-A2: 数据库表结构

**新增文件**: `supabase/migrations/20251230000000_add_user_management.sql`

创建了以下数据库结构：

1. **users 表** - 用户账户
   - `id`, `username`, `password_hash`, `role`, `display_name`, `email`
   - `is_active`, `created_at`, `updated_at`, `last_login_at`
   - 索引: `idx_users_username`, `idx_users_role`

2. **documents 表修改** - 添加所有权字段
   - `owner_id` - 所有者 ID (users.id 或 session_id)
   - `owner_type` - 所有者类型 (system/admin/user/guest)
   - `expires_at` - 过期时间 (Guest 文档)
   - 索引: `idx_documents_owner`, `idx_documents_expires`

3. **guest_activity 表** - 访客活动统计
   - `session_id`, `ip_address`, `user_agent`
   - `message_count`, `upload_count`, `extract_count`
   - `created_at`, `last_activity_at`, `expired_at`

### A3: Admin 账户初始化

**新增文件**: `src/lib/auth/user-service.ts`

- `ensureAdminAccount()` - 启动时检查/创建 admin 账户
- `authenticateUser()` - 用户名密码验证
- `findUserByUsername()`, `findUserById()` - 用户查询

### A4: TypeScript 类型

**修改文件**: `src/lib/database/types.ts`

- 新增 `UserRole`, `OwnerType` 类型
- 新增 `users` 表类型定义
- 新增 `guest_activity` 表类型定义
- 更新 `documents` 表类型 (添加 owner 字段)

### 测试期间发现的问题

1. **ADMIN_PASSWORD 环境变量解析** - `.env.local` 中的 `$` 字符被 dotenv 作为变量引用展开
   - 修复: 使用 `\$` 转义或确保正确引用

2. **ensureAdminAccount 双重哈希** - 若 ADMIN_PASSWORD 已是 bcrypt 哈希，会再次哈希
   - 修复: 添加 `startsWith('$2')` 检测，已是哈希则直接使用

### 部署确认

- **容器状态**: Running
- **健康检查**: `{"status":"ok"}`
- **清理调度器**: 每小时运行，已清理过期文档
- **Redis 连接**: 正常（使用 host.docker.internal 或主机 IP）
