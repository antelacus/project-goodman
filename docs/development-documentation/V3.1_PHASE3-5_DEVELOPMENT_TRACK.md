**目录结构**:
```

├── steps.ts  (658 行) - 5 个步骤函数
└── index.ts  (117 行) - 工作流编排器
```

**步骤函数**:

1. **routeToFunction** - 路由问题到合适的函数
   - 调用 OpenAI 选择 preset function 或 get_financial_metric
   - 更新 `state.routing`

2. **queryData** - 查询财务数据
   - 从数据库查询所需指标
   - 处理 fuzzy matching (模糊匹配)
   - 更新 `state.dataQuery`

3. **executeCalculation** - 执行计算
   - 使用 preset function 计算或执行数据对比
   - 更新 `state.calculation`

4. **evaluateConfidence** - 评估置信度
   - 计算综合置信度分数
   - 检查是否通过阈值
   - 更新 `state.confidence`

5. **generateResponse** - 生成自然语言响应
   - 调用 OpenAI 生成解释
   - 构建最终输出
   - 更新 `state.output`

**工作流编排器**:
```typescript
export async function runFinancialAnalysisWorkflow(
  input: FinancialAnalysisState["input"]
): Promise<FinancialAnalysisState> {
  let state = initializeState(input);

  state = await steps.routeToFunction(state);
  if (!state.routing.selectedFunction) {
    return await steps.generateResponse(state);
  }

  state = await steps.queryData(state);
  if (state.dataQuery.missingMetrics.length > 0) {
    return await steps.generateResponse(state);
  }

  state = await steps.executeCalculation(state);
  state = await steps.evaluateConfidence(state);

  if (!state.confidence.passed) {
    return await steps.generateResponse(state);
  }

  return await steps.generateResponse(state);
}
```

   - 基于引用的法规查找相关条款
   - 排除已在主引用中的条款
   - 更新 `state.relatedArticles`

   - 计算语义相似度、引用数量、上下文相关性
   - 检查是否通过阈值 (0.6)
   - 更新 `state.confidence`

5. **generateResponse** - 生成最终响应
   - 构建完整输出结构
   - 包含指导、引用、相关条款、计算结果
   - 更新 `state.output`

```typescript
export async function runGuidanceChatWorkflow(

): Promise<GuidanceChatState> {

    return earlyExitNoResults(state);

  state = await steps.generateGuidance(state);
  state = await steps.findRelatedArticles(state);
```

### 使用示例

```typescript
// 步骤函数中抛出错误
import { InsufficientDataError, LowConfidenceError } from '@/lib/errors';

export const queryData: StepFunction<State> = async (state) => {
  const results = await fetchData();

  if (results.missing.length > 0) {
    throw new InsufficientDataError(results.missing, { step: 'queryData' });
  }

  return { ...state, data: results };
};

// 工作流编排器处理错误
import { WorkflowError, isRecoverableError, toWorkflowError } from '@/lib/errors';

try {
  state = await steps.queryData(state);
} catch (error) {
  if (isRecoverableError(error)) {
    // 尝试备用策略
    state = await steps.tryAlternativeSource(state);
  } else {
    // 记录错误到状态
    state.meta.errors.push(toWorkflowError(error));
    throw error;
  }
}
```

- ✅ TypeScript 编译通过
- ✅ 所有错误类型正确继承 WorkflowError
- ✅ toJSON() 输出与 SerializedWorkflowError 接口匹配
- ✅ 与现有 WorkflowMeta.errors 向后兼容

### 设计决策

#### ADR-008: 错误可恢复性策略

**决策**: 每个错误类型有固定的 `recoverable` 属性，`WorkflowStepError` 除外

**理由**:
- 工具错误、数据错误、置信度错误通常可恢复（尝试备用策略）
- 超时、无效状态不可恢复（需要用户干预）
- `WorkflowStepError` 可配置以适应不同场景

#### ADR-009: 错误序列化策略

**决策**: 使用 `SerializedWorkflowError` 接口存储状态中的错误

**理由**:
- 状态需要可序列化（JSON 兼容）
- 错误类实例不能直接存储在状态中
- `toJSON()` 和 `toWorkflowError()` 提供转换桥梁

- 步骤函数抛出错误，编排器捕获
- 更符合 LangGraph 条件边模式
- 集中化错误处理逻辑
