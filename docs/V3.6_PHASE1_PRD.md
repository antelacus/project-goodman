## 1. 概述

### 1.1 背景

Project Goodman 在 V3.0-V3.5 阶段完成了：
- VPS 迁移（无超时限制）
- LangGraph 框架集成
- 智能文档系统
- Agent 逻辑升级（工具调用、记忆）

然而，当前 UI 仍保留传统的"模块导航"模式，要求用户在「财务信息提取」「财务指标分析」「财务合规指导」三个模块之间自行选择。这与现代 AI 应用的交互范式不符。

### 1.2 核心问题

| 问题 | 影响 |
|------|------|
| **选择负担** | 用户必须先判断任务属于哪个模块 |
| **跨模块任务受阻** | "计算流动比率并检查合规性"需要切换页面 |
| **无实时反馈** | 长时间任务时用户看不到系统状态 |
| **入口分散** | 三个独立入口，无统一工作台 |

### 1.3 解决方案

构建 **统一对话工作台 (Unified Chat Workspace)**：

- **单一入口**: 一个对话框完成所有任务
- **统一 Agent**: 单一 StateGraph，通过工具调用实现所有功能（无子 Agent）
- **扁平工具架构**: 原"模块"功能转化为 toolRegistry 中的工具
- **实时流式响应**: WebSocket 推送思考过程
- **富结果渲染**: 计算卡片、引用卡片、文档来源在对话中内嵌显示

### 1.4 核心架构洞察

**关键发现**: 现有的三个"模块"（财务分析、合规指导、信息提取）在 LangGraph 层面并非本质不同：

| 方面 | 财务分析模块 | 合规指导模块 | 结论 |
|------|-------------|-------------|------|
| **Graph 结构** | agent → tool → agent 循环 | agent → tool → agent 循环 | **相同** |
| **工具执行** | 使用 toolRegistry | 使用 toolRegistry | **相同** |
| **记忆管理** | conversationMemory | conversationMemory | **相同** |
| **差异点** | 系统提示词、暴露的工具子集 | 系统提示词、暴露的工具子集 | 仅配置不同 |

**结论**: 无需创建"子 Agent"，只需一个统一的 StateGraph + 扩展的工具集。"模块"概念将消解为"工具类别"。

## 2. 目标用户与场景

### 2.1 用户画像

| 属性 | 描述 |
|------|------|
| **角色** | 企业会计部门财务人员 |
| **典型职位** | 财务分析师、会计、财务主管 |
| **技术水平** | 熟练使用 Excel，不熟悉编程 |
| **核心需求** | 快速获取财务指标、合规解答、文档信息提取 |
| **使用场景** | 日常财务分析、月度/年度报告准备、合规检查 |

### 2.2 典型使用场景

**场景 1: 综合财务分析**
```
用户: "帮我计算2024年的流动比率和速动比率，并分析是否符合行业标准"

Agent 行为:
1. 识别意图: 财务指标计算 + 合规/标准对比
2. 调用财务分析工具获取流动比率、速动比率
3. 调用合规指导工具查询行业标准
4. 综合回答，附带计算步骤和法规引用
```

**场景 2: 文档信息提取**
```
用户: "我需要从一份发票中提取信息"

Agent 行为:
1. 识别意图: 信息提取
2. 提示用户上传文件
3. 用户上传后，调用提取工具
4. 在对话中返回结构化提取结果
```

**场景 3: 多轮对话**
```
用户: "2024年ROE是多少？"
Agent: "2024年ROE为15.3%，计算过程如下..."

用户: "与2023年相比如何？"
Agent: (利用对话记忆) "2023年ROE为12.8%，增长了2.5个百分点..."

用户: "这个增长幅度是否合理？参考一下相关法规"
Agent: (跨模块调用) "根据《企业财务通则》..."
```

## 3. 当前状态 vs 目标状态

### 3.1 架构对比

**当前 (V3.5) - 多 Graph 分离架构**:
```
Landing Page (营销页)
      │
      ├── /data-extract       → 独立逻辑 (无 LangGraph)
      │
      ├── /financial-analysis → FinancialAgentGraph (StateGraph)
      │                              ├── loadMemory → agentNode ↔ toolNode → response
      │                              └── Tools: 22 财务计算 + query + get_metric
      │
      └── /guidance-chat      → GuidanceAgentGraph (StateGraph)
                                     ├── loadMemory → agentNode ↔ toolNode → response
                                     └── Tools: search_regulations + query_data

问题: 3 个独立入口，Graph 结构重复，工具分散
```

**目标 (V3.6) - 单一 Graph 扁平工具架构**:
```
Landing Page (营销页 + "开始对话" CTA)
      │
      └── /chat → 统一对话工作台
                    │
                    └── UnifiedAgentGraph (单一 StateGraph)
                          │
                          ├── Nodes (复用现有结构):
                          │     loadMemory → agentNode ↔ toolNode → response
                          │
                          ├── Tools (扁平注册到 toolRegistry):
                          │     ├── 财务计算类 (22个): current_ratio, roe, ...
                          │     ├── 数据查询类: query_financial_data, get_financial_metric
                          │     ├── 合规搜索类: search_regulations, search_documents (新增)
                          │     └── 信息提取类: extract_document_info (新增)
                          │
                          └── System Prompt: 统一提示词 (覆盖所有能力)

优势: 单一入口，统一 Graph，扁平工具，Agent 自动选择
```

### 3.2 LangGraph 概念映射

| 概念 | V3.5 现状 | V3.6 目标 |
|------|----------|----------|
| **StateGraph** | 每模块一个 (3个) | 统一为 1 个 |
| **Nodes** | 重复定义 | 复用现有 nodes |
| **Tools** | 分散在各模块 | 统一注册到 toolRegistry |
| **System Prompt** | 每模块独立 | 单一统一提示词 |
| **Agent Loop** | agent ↔ tool | 相同 (复用) |

### 3.3 用户体验对比

| 维度 | 当前 | 目标 |
|------|------|------|
| **入口** | 3 个独立页面 | 1 个统一对话 |
| **意图识别** | 用户自行判断 | Agent 自动识别 |
| **跨模块任务** | 需切换页面 | 单次对话完成 |
| **加载反馈** | 静态 loading | 实时思考过程 |
| **对话记忆** | 模块内有限 | 跨模块持久 |

### 3.4 页面路由变更

| 路由 | 当前用途 | V3.6 后状态 |
|------|----------|-------------|
| `/` | 营销 Landing | 保留，新增 "开始对话" CTA |
| `/chat` | 不存在 | **新增**: 统一对话工作台 |
| `/data-extract` | 信息提取页 | **移除**: 功能集成到 /chat |
| `/financial-analysis` | 财务分析页 | **移除**: 功能集成到 /chat |
| `/guidance-chat` | 合规指导页 | **移除**: 功能集成到 /chat |
| `/documents` | 文档管理 | 保留不变 |
| `/help`, `/about` | 帮助页 | 保留不变 |

## 6. 分阶段实施计划

### 6.1 V3.6a: 统一 Agent + 扁平工具架构

**目标**: 后端能力就绪，API 可用

**核心思路**: 先重构文件结构消除重复，再扩展工具集，最后创建统一 Agent

#### 6.1.1 前置任务：文件重组 (Reorganization)

**问题**: 现有代码存在显著重复，阻碍统一 Agent 实现：
- `financial-analysis/nodes.ts` 与 `guidance-chat/nodes.ts` 有 ~400 行重复代码
- 工具文件平铺，无分类结构
- `/lib` 根目录 23 个文件，难以导航

| 任务 | 描述 | 类型 |
|------|------|------|
| 提取共享 Nodes | 将 `loadMemoryNode`, `agentNode`, `toolNode`, `saveMemoryNode` 提取到 `workflows/core/nodes/` | 重构 |
| 提取共享 Edges | 将 `afterAgentNode`, `afterToolNode` 路由逻辑提取到 `workflows/core/edges/` | 重构 |
| 创建工具分类目录 | `tools/financial/`, `tools/compliance/`, `tools/extraction/` | 重构 |
| 统一类型定义 | 修复 `guidance-chat` 中 `any[]` 类型为强类型 | 重构 |

**目标文件结构** (详见 Phase 2 Design 文档):

```
src/lib/workflows/
├── unified/           ← 新：统一 Agent
├── core/              ← 新：共享组件
│   ├── nodes/
│   ├── edges/
│   └── state/
└── [legacy]/          ← 旧模块 (V3.6c 后废弃)

src/lib/tools/
├── financial/         ← 重组：财务工具
├── compliance/        ← 新：合规工具
└── extraction/        ← 新：提取工具
```

#### 6.1.2 核心任务：统一 Agent 实现

| 任务 | 描述 | 复用/新建 |
|------|------|----------|
| 创建统一 Agent Graph | 基于 `workflows/core/` 共享组件构建 | 新建 (复用 core nodes) |
| 添加合规搜索工具 | `search_regulations`, `search_documents` | 新建 (封装现有逻辑) |
| 添加信息提取工具 | `extract_document_info` | 新建 (封装现有逻辑) |
| 创建统一系统提示词 | 合并现有 3 个模块的提示词能力 | 新建 |
| 创建统一 API 端点 | `/api/chat` 调用 UnifiedAgentGraph | 新建 |
| 工具注册函数 | `registerAllTools()` 一次性注册所有工具 | 新建 |

#### 6.1.3 工具清单 (V3.6a 目标)

```
toolRegistry
├── tools/financial/ (现有，重组)
│   ├── calculation-tools.ts   ← 22个预设函数
│   └── query-tools.ts         ← query_financial_data, get_financial_metric
│
├── tools/compliance/ (新增)
│   ├── search-regulations.ts  ← 封装 guidance-chat 法规搜索
│   └── search-documents.ts    ← 封装 hybrid search 逻辑
│
└── tools/extraction/ (新增)
    └── extract-document.ts    ← 封装 data-extract 提取逻辑
```

**交付物**:
- 重组后的清晰文件结构
- 可通过 `/api/chat` 测试的统一 Agent（无流式，同步响应）
